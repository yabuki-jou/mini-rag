## What this software does

该项目为员工提供一个企业制度与行政业务助手。用户可以上传企业制度文件并建立可检索知识库，通过自然语言询问制度、查询自己的假期余额和申请记录，也可以让助手收集请假参数。请假写入前系统会展示草稿并暂停，只有用户明确批准后才写入业务数据库。一次成功运行不仅要生成自然语言回答，还必须选对工具、使用当前会话授权范围、返回真实引用，并阻止未确认或重复写入。

## Target users and value proposition

目标用户是学习 AI 应用开发与 Agent 开发的开发者，以及可信小范围内进行演示的员工用户。它把 RAG、Tool Calling、LangGraph 多轮状态、人工确认、FastAPI、SQLite 和 Milvus 放在一个可运行项目中，价值不在于自由聊天，而在于展示“模型负责理解和候选参数、确定性代码负责权限和业务事实、Graph 负责流程控制”的可审计业务闭环。当前 `X-User-ID` 只是学习阶段身份模拟，不适合公开互联网部署。

## Capability inventory

1. 企业制度检索：在当前 Agent 会话绑定的知识库中检索制度 Chunk，并生成带文档名、页码和分数来源的回答。
2. 假期余额查询：识别年假或病假类型，并只查询当前用户关联员工的对应余额。
3. 请假申请查询：列出当前用户最近 20 条申请，或按 UUID 查看其中一条详情。
4. 多轮参数收集：当请假类型、日期或原因不完整时继续追问，而不是猜测或提前调用写工具。
5. 人工确认写入：生成无副作用请假草稿，通过 interrupt 暂停，并在批准后幂等写入或在拒绝后保持零写入。
6. 会话和历史：使用 AgentSession 绑定用户、知识库和 LangGraph thread，通过 Checkpoint 跨 HTTP 请求保存消息与待确认状态。
7. 权限和观测：验证会话所有权，隐藏模型不可见的身份字段，并提供不含自由文本正文和内部异常的工具调用审计。

## Realistic input characteristics

- 用户消息通常为 5–500 个中文字符，可能包含口语、省略、相对日期、错别字、多个意图或不完整请假参数；HTTP Schema 上限为 2,000 字符。
- 制度问题来自真实企业行政语境，例如年假资格、费用报销上限、病假证明和培训规则，答案可能分布在 1–3 个召回 Chunk 中；单个 Chunk 最大约 8,192 字符，最终最多向模型提供 3 个合格 Chunk。
- 请假请求包含 `ANNUAL`/`SICK`、起止日期和 1–500 字符原因，日期范围可能跨周末、余额不足或与现有申请重叠。
- 对话是多轮的：一次业务意图可能经过 2–5 轮补参，人工确认发生在另一个 HTTP 请求中；同一个确认请求也可能因客户端重试而重复到达。
- 用户与知识库 UUID、员工身份和 Graph thread 都由服务端上下文提供，现实风险包括其他用户尝试访问已知会话 UUID，或提示注入要求模型伪造身份和绕过确认。

## Hard problems and failure modes

1. 工具选择错误：制度问题被直接凭常识回答，余额问题调用制度检索，或普通问候误触发业务工具。
2. 参数收集错误：模型在缺少日期、类型或原因时自行猜测，生成不合法日期或把多个写操作放在同一轮。
3. 引用幻觉：回答包含制度断言但没有引用，引用编号与真实 Chunk 不一致，或在无合格检索结果时编造答案。
4. 越权访问：模型或客户端试图提供 `user_id`、`kb_id`、`employee_id`，导致查询其他用户知识库、余额或申请。
5. 确认绕过和重复写入：草稿阶段产生数据库副作用、普通消息绕过 decisions 接口、错误 action ID 被接受，或重复 resume 创建两条申请。
6. 状态恢复错误：HTTP 请求使用错误 thread、Checkpoint 损坏或中断动作与当前界面展示的 action ID 不一致。
7. 外部依赖失败：DeepSeek、Milvus、本地 Embedding 或 Checkpoint SQLite 超时/断开；只应重试瞬时连接类故障，不能重试权限和业务校验错误。
8. 敏感信息泄露：工具参数、制度正文、请假原因、Token、密码、异常堆栈或隐藏推理进入工具日志或 HTTP 错误响应。
