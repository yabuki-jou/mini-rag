# Project Analysis

## What this software does

本软件是面向个人学习和小范围演示的企业知识库与智慧档案后端。使用者可在受
权限隔离的工程项目中上传文档、解析并人工确认归档资料，再在仅限已确认档案
的范围内检索原文或提出问题。一次成功的业务闭环应给出可追溯的原文证据和引用，
并在删除时同步处理原文件、业务记录和向量；它不应把 AI 建议或未确认资料当作
正式业务事实。

## Target users and value proposition

目标用户是学习 FastAPI、RAG、Agent 编排和企业文档工作流的开发者，以及使用
虚构或脱敏工程资料进行小范围演示的用户。相较于仅回答问题的通用聊天界面，
该系统把项目所有权、人工确认、清单关联、证据引用、脱敏审计和跨存储删除纳入
同一条业务链路，使“回答来自哪份已确认资料”可以被检查。

## Capability inventory

1. 项目与清单管理：创建受用户所有权约束的项目，并维护项目内资料清单和派生缺失状态。
2. 文档摄取与处理：接收 TXT、Markdown、PDF、DOCX，保存原文件、解析有效文本并记录可重试失败状态。
3. 人工归档与确认：维护字段、证据、人工检查、确认/取消确认和正式目录状态。
4. 受控检索：仅在当前项目的 `CONFIRMED` 文档集合内，通过 PostgreSQL 范围和 Chroma 过滤检索证据片段。
5. 带证据问答与 AI 建议：由 DeepSeek 仅依据已检索证据提出建议或回答；没有充分依据时拒答。
6. 物理删除与审计：阻断待删文档的可见性，清理文件、向量和业务记录，并保留脱敏操作审计。

## Realistic input characteristics

输入是单项目内的虚构或脱敏工程归档资料及自然语言问题。单个文件支持 TXT、
Markdown、文本型 PDF、DOCX，最大 20 MiB；有效文本长度规则为 20 至 1,000,000
字符。内容可能含标题、编号、日期、阶段、合同/验收信息、章节、页码、段落、
不同格式的定位信息和缺失字段；扫描件或无有效文本文件必须被识别为失败，而非
被伪造解析。质量验收问题至少应覆盖 8 个可由当前项目证据回答的问题、2 个无依据
问题和 2 个项目隔离问题；真实评估资料必须是独立准备的虚构/脱敏资料。

## Hard problems and failure modes

1. 检索阈值未标定：向量距离方向、阈值和 Top-K 选择不当会遗漏标准证据或引入无关片段。
2. 证据约束被绕过：模型可能补全原文未出现的信息、给出错误引用，或把非正式资料当作依据。
3. 无依据问题的误答：检索没有充分证据时仍生成断言性答案或伪造引用。
4. 项目隔离泄露：过滤条件、确认状态集合或权限上下文缺失时可能暗示其他项目内容。
5. 解析失败处理不一致：扫描件、空文本或无效格式未稳定记录失败状态，重试和人工处理失去边界。
6. 跨存储删除半完成：Chroma 或文件系统不可用时，数据库仍宣称删除成功，造成可检索残留。

## D5 最小工程验证边界

D5 为正式档案问答链路准备最小工程评测材料，不声称完成 P14 固定 12 题验收。
`ArchiveQuestionRunnable` 直接调用生产 `answer_archive_question()`；Pixie 通过
`archive_question_retrieval` 输入边界注入完整、可反序列化的虚构候选，便于在不依赖
PostgreSQL/Chroma 的情况下检查评测工程。主 Agent 将基于该材料执行真实 smoke。
数据集包含四类问题：唯一直接证据、多个候选中的
支持性证据、主题相近但缺关键事实，以及高分但无直接证据。后两类专门观察候选存在
是否被错误地当成事实充分，以及模型是否保持拒答边界。

D5 本轮实际覆盖的子能力为：直接证据回答、多个候选中的引用选择、候选非空时的
证据不足拒答，共 `3/3`；不把上传、解析、删除等项目级能力计入这个窄范围 smoke。
生产问答最多接收 5 个原文 Chunk，本轮候选数分布为 1、2、1、1，覆盖了唯一证据和
干扰候选，但尚未覆盖 5 个长 Chunk。难度分布为 1 个常规、1 个中等、2 个困难案例，
四条候选来自四组不同的虚构项目文本，未使用 `tests/fixtures` 或历史请假样本。
