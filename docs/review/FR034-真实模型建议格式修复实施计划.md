# FR-034 真实模型建议格式修复实施计划

## 问题与证据

真实 Vue → Vite `/api` → FastAPI → DeepSeek 链路对虚构 PDF 首次建议与专用重试均返回 `422 SUGGESTION_INVALID_OUTPUT`。独立结构诊断确认 DeepSeek 可以返回合法 JSON 和顶层 `fields`，但七个字段键使用中文名称，而生产解析器只接受 `TITLE`、`DOCUMENT_TYPE`、`DOCUMENT_DATE`、`AUTHORING_ORGANIZATION`、`VERSION_NUMBER`、`PROJECT_STAGE`、`KEYWORDS`。

当前 `_build_prompt` 只要求“七个固定字段”，没有声明固定键名、三种值列、枚举值、空值规则和证据对象结构；现有 Mock 测试直接返回理想结构，因此不能证明真实模型遵守契约。

## 修复范围

只修改 `app/services/archive/suggestions.py` 及现有测试 `tests/routers/test_project_document_suggestions.py`。不修改 HTTP API、数据库结构、字段枚举、状态机、前端或其他 LLM 链路。

## TDD 步骤

1. RED：新增 Prompt 契约测试，要求 Prompt 明确包含七个英文固定字段键、资料类型和项目阶段允许值、各字段唯一值列、`null` 空值、证据对象字段、证据定位必须来自快照，以及“只输出裸 JSON”约束。
2. RED：新增模型调用测试，要求建议链路为 DeepSeek 调用绑定 `response_format={"type":"json_object"}`；只对连接和超时重试一次的既有行为必须保持。
3. GREEN：最小增强 `_build_prompt`，给出完整、唯一、机器可执行的 JSON Schema 说明；在建议模型调用上启用 JSON Object 模式。
4. REFACTOR：更新既有 Fake Model 以支持同一绑定接口，不放宽生产解析器，不接受中文别名、Markdown 围栏或额外猜测映射。
5. 运行建议服务/路由定向测试、完整 `pytest`、`compileall` 和 `git diff --check`。

## 真实验收

自动测试通过后，使用当前临时虚构项目的新文档再次执行真实 DeepSeek 建议。通过条件为：HTTP 200、状态 `PENDING_CONFIRMATION`、返回七字段、所有非空 AI 值均有当前快照证据；若仍失败，保留稳定错误与 `SUGGESTION_FAILED` 状态并继续基于结构诊断定位，不能以 Mock 结果宣称通过。
