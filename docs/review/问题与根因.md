# 问题与根因

## 1. archive_sessions 循环导入

**日期：** 2026-09-26

**问题**

`app.services.agent.archive_sessions` 无法独立导入。

**根因**

Service 为使用 `ProjectContext` 导入 `dependencies`，
而 `dependencies` 初始化过程中又反向导入该 Service，
形成循环依赖。

**修复**

`find_latest_archive_agent_session()` 改为显式接收
`user_id`、`project_id`、`kb_id` 和 `session`，
由 Router 从已验证的 `ProjectContext` 中展开传入。

**验证**

冷导入恢复正常，相关 Service、Router、OpenAPI 测试共 8 项通过。

## 2. 历史读取依赖完整 Agent Runtime

**日期：** 2026-09-26

**问题**

档案助手历史接口读取已有消息时会构建完整 Agent Runtime，导致模型配置缺失或模型客户端初始化失败时，历史消息也无法读取。

**根因**

历史读取实际只需要恢复 Checkpoint 状态，但原实现复用了消息执行所需的完整 Runtime 构建入口。

**修复**

历史 Service 改为直接打开现有 Checkpoint，通过保持相同 State、Reducer、节点名称和拓扑的轻量 Graph，使用 LangGraph 公开的 `get_state()` 恢复历史状态。

消息发送仍使用完整 Runtime。

**验证**

相关 Service、Router、状态恢复和错误处理测试共 **43 项通过**，包括 pending writes、模型不可用、鉴权及 Checkpoint 异常场景。
