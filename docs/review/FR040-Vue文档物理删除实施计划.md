# FR-040 Vue 文档物理删除实施计划

## 1. 目标与边界

本切片把后端已经实现的 FR-040 项目文档物理删除接入相邻 Vue 工作台。用户可以从当前项目的文档处理列表发起删除，经明确确认后调用项目级删除接口；成功后页面同步移除文档并刷新由该文档派生的清单、正式档案和问答状态，失败时展示后端稳定错误并允许再次调用同一入口恢复未完成删除。

本切片不修改后端公开 API、数据库结构、跨存储删除顺序、可见性阻断规则或审计结构；不接入 FR-041 审计查询，不增加批量删除、软删除、回收站或客户端伪造的删除状态。

## 2. 已确认契约

- `DELETE /projects/{project_id}/documents/{document_id}` 成功返回 `204 No Content`。
- 删除可以从任一稳定用户可见文档状态发起；存在解析、建议、确认或另一删除操作时，后端返回 `409 DOCUMENT_OPERATION_IN_PROGRESS`。
- 外部存储删除未完成时，后端返回 `503 DOCUMENT_DELETE_INCOMPLETE`，并以内部 `visibility_blocking` 使文档立即退出正式目录、检索和问答范围；同一删除接口是恢复入口。
- 处理列表仍返回尚未完成物理删除的文档，并继续使用 `ArchiveDocumentStatus` 展示原归档状态。前端不得新增 `DELETE_FAILED` 归档状态；失败后保留该行和删除按钮，用户可再次确认并重试。
- 后端成功删除 Final Chunk、原文件、解析快照、字段、证据、清单关联、档案和文档事实，并更新项目文档计数；前端只消费结果，不推断跨存储步骤是否完成。
- 身份、项目和知识库范围由 Bearer 会话及后端依赖校验；前端不提交用户或知识库标识。跨项目文档必须由后端拒绝且不得泄露目标事实。

## 3. 实现步骤

1. 在 API 层新增项目文档删除方法，精确调用 FR-040 路由，不复用旧知识库工作台的删除接口。
2. 在 Pinia Store 新增单文档删除动作：
   - 以 `delete-project-document:{document_id}` 保存逐行加载状态并防止重复提交；
   - 成功后只在发起删除的项目仍为当前项目时更新界面，移除该文档、修正列表总数和项目活动文档数；
   - 若当前草稿、正式档案详情或清单关联面板属于被删文档，立即清空对应状态；
   - 使当前检索、问答及在途请求失效，避免继续展示已删除证据；
   - 重新读取处理列表、清单和正式档案，使分页、缺失状态和目录均以服务端事实为准；当前页删除后为空且页码大于 1 时回到上一页；
   - 若删除返回错误，保留原稳定错误及 HTTP 状态，并尝试刷新处理列表、清单和正式档案；刷新失败不得遮蔽原删除错误。`503` 后文档行仍可再次删除。
3. 在文档处理面板为每一行增加明确的删除入口，逐行禁用并显示删除中状态；面板只发出文档标识和文件名，不自行调用 API 或确认。
4. 在工作台视图收到删除事件时，使用包含文件名和物理清理影响的确认文本；取消不调用 Store，确认后调用 Store 删除动作。
5. 保持旧知识库工作台及其删除接口不变，不扩大到审计查询。

## 4. TDD 与验收

### RED

先增加并实际运行失败测试，至少覆盖：

- API 的精确 URL 和 `DELETE` 方法；
- 文档处理面板始终提供删除入口、发出文档标识与文件名，并按单行加载状态禁用；
- 工作台取消确认时不删除，确认时只调用一次当前项目 Store 动作；
- Store 成功后移除文档、修正计数、清理当前文档和检索问答状态，并刷新处理列表、清单和正式档案；
- Store 在当前页删除后为空时回退分页；
- Store 收到 `DOCUMENT_DELETE_INCOMPLETE` 时保留原错误、刷新真实状态且允许重试；
- 删除请求期间切换项目时，旧项目的成功、失败和刷新结果均不污染新项目状态。

### GREEN

只实现使上述行为通过的最小前端代码，不修改后端生产删除服务、公开契约或扩大到 FR-041。

### 最终验证

1. 运行新增与相关前端测试。
2. 运行前端完整测试、`typecheck` 和 `build`。
3. 运行后端 FR-040 相关测试、完整测试和 `compileall`。
4. 使用明确标记的临时测试用户、项目和文档，经真实 `5173/api -> 8000 -> PostgreSQL/Chroma` 链路验收：
   - 已确认且满足必需清单项的档案删除成功；
   - 页面文档行和正式档案消失，项目文档计数减少，清单重新显示缺失；
   - 原文件、向量、档案和关联均已清理，删除审计仍保留；
   - 删除后的原文不能再被检索或用于问答；
   - 浏览器无控制台错误，刷新后仍与服务端状态一致。
5. 精确清理其余临时测试数据，再更新 README、学习计划与交接文档。

真实浏览器点击“确认删除”属于破坏性 UI 操作。实现、自动化测试和临时数据准备完成后，主 Agent 必须在点击前按 computer-use 技能要求取得当次明确确认。

## 5. 停止条件

若实现需要改变公开 API、核心数据库结构、删除恢复语义、跨存储清理顺序、可见性阻断或审计内容，Luna 停止扩大修改并交回主 Agent 重新评审。
