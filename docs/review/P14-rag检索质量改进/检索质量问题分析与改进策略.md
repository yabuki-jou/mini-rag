本台账区分“已证实事实”“合理推测”和“尚未验证”，不把局部成功写成质量通过。固定集门槛始终是：

```text
有据命中 >= 7/8
无据拒答 = 2/2
项目隔离 = 2/2
```

## 1. 固定集与链路

固定集包含 8 个有据问题、2 个无据问题和 2 个项目隔离问题，来自 AV1-P02 已冻结的虚构资料与
Ground Truth。正式链路为：

```text
Bearer 身份与项目授权
→ PostgreSQL 取得 CONFIRMED 且未被删除阻断的 document_id
→ BGE 查询向量
→ Chroma 按 user_id + project_id + kb_id + document_id 召回 Top-10
→ 校验候选元数据和范围
→ 本地 Reranker（阶段 C）重排
→ 按当前独立阈值筛选并返回原始 Final Chunk 引用
```

## 2. 阶段 A：纯稠密诊断（2026-08-31）

### 实验变量

- 使用同一固定 12 题和同一确认—INDEX 数据，仅增加逐题脱敏诊断。

### 环境

- 健康的本机 API、PostgreSQL、Chroma 和 512 维 BGE；未改变检索行为。

### 固定集结果

- 标准证据均进入前 3 候选：6 题第 1、1 题第 2、1 题第 3。
- 完整候选：有据 `8/8`、无据拒答 `0/2`、隔离 `2/2`。
- 拒绝全部无据候选时：有据 `5/8`、无据拒答 `2/2`、隔离 `2/2`。

### 脱敏诊断

- 逐题记录只保留稳定题号、dense 排名和距离字段，不输出正文或资源标识。

### 已证实事实

- 未出现 `OUT_OF_SCOPE` 候选。
- 正确证据通常已经进入 Chroma 候选集；阶段 A 排除了“全部正确证据未召回”和“范围过滤失效”作为主因。

### 仍属推测的内容

正确证据和错误/无据候选的 dense distance 可能不可分；这只是排序层推测。

### 对下一决策的影响

该结果支持进入阶段 B，但不支持冻结阈值或开始 P12。

## 3. 阶段 B：`evidence_values` 索引（2026-08-31）

### 实验变量

- 只把当前快照中已确认、具有定位且锚点匹配的字段值注入对应 Final Chunk 的向量输入。
- 不改变原文引用、定位、Chunk ID、项目授权或固定集 Ground Truth。

### 环境

- 复用本机 `8000` 的真实 PostgreSQL、Chroma 和 BGE 链路。

### 固定集结果

- 12 份文档获得字段上下文，覆盖 63 个 Chunk，零覆盖文档为 0。
- 完整候选：有据 `7/8`、无据拒答 `0/2`、隔离 `2/2`。
- 拒绝全部无据候选时：有据 `3/8`、无据拒答 `2/2`、隔离 `2/2`。

### 脱敏诊断

- 12 份文档获得字段上下文，覆盖 63 个 Chunk，零覆盖文档为 0。

### 已证实事实

字段映射实际生效，但该表示未通过门槛且劣于阶段 A 的 `5/8` 上限。因此不冻结默认模式或阈值。

### 仍属推测的内容

仅凭该轮结果不能证明字段值模式是召回下降的唯一原因。

### 对下一决策的影响

不自动调整 Chunk 粒度；阶段 B 当时的本地 Reranker 需单独授权，后续已在阶段 C 边界确认中获得授权。

## 4. 阶段 C：本地 Reranker 接入（2026-09-01）

### 实验变量

- 仅对授权和 Chroma 元数据校验后的 Top-10 候选使用本地 `BAAI/bge-reranker-base`。
- 不引入 BM25、混合召回、远程排序、跨项目检索或 Chunk 切分调整。
- 保留兼容 dense `score`，以独立 `reranker_score` 进行排序和阈值标定。

### 环境

- 复用真实 PostgreSQL、Chroma、512 维 BGE 和本地 Reranker 链路。

### 固定集结果

- 完整候选：有据 `7/8`、无据拒答 `0/2`、隔离 `2/2`。
- 拒绝全部无据候选时：有据 `3/8`、无据拒答 `2/2`、隔离 `2/2`。
- 不存在同时满足门槛的独立重排阈值。

### 脱敏诊断

- 本阶段仅记录聚合结果，未覆盖“标准证据是否进入完整 Top-10”的双排序归因；该缺口由 C.1 补足。

### 已证实事实

Reranker 不能在当前候选和分数分布上同时保留有据结果并拒绝无据问题。该结果本身不说明是召回
缺失还是重排不可分。

### 仍属推测的内容

召回缺失和重排不可分可能同时存在，需用同一候选池的两套排名分别验证。

### 对下一决策的影响

进入 C.1 双排序诊断；P12 仍阻塞。

## 5. 阶段 C.1：双排序诊断（2026-09-01）

### 实验变量

- 只增强固定集运行器的安全诊断，复用健康的本机 `8000` 服务。
- 不启动临时 `8002`，不改变线上检索、模型、候选池、Chunk 或阈值。

### 环境

- 健康的本机 `8000`、PostgreSQL、Chroma、512 维 BGE 和本地 Reranker。
- dense 排名由 `score = 1 - distance` 重建；Reranker 排名读取正式响应顺序。

### 固定集结果

- 聚合结果仍为有据 `7/8`、无据拒答 `0/2`、隔离 `2/2`；不存在可冻结阈值。

### 脱敏诊断

- `GROUNDED-07` 的 `candidate_count=10`，但标准证据的 dense 与 Reranker 排名均为空，直接证实
  正确证据未进入 Chroma Top-10，属于召回缺失。
- 两个无据题的最高 Reranker 分数为 `0.981258`、`0.696090`，对应同一候选的 dense distance
  为 `0.289213`、`0.334844`，说明无据候选仍无法由当前独立分数阈值全部拒绝。

### 已证实事实

- 至少一题的主问题是 Chroma 召回缺失，而不是 Reranker 将已召回证据排除。
- 无据候选的高 Reranker 分数仍是独立阻塞因素；不能仅凭修复召回就宣称 P14 通过。
- 本轮虚构账号、项目、文档和内部知识库已清理为零。

### 仍属推测的内容

- 仅凭 `GROUNDED-07` 不能推断所有有据题都需要 Chunk 调整。
- 无据题的高分是否可通过候选池或查询表达改变，尚未在授权范围内验证。

### 对下一决策的影响

- 尚未授权任何新的检索行为变更，因此没有实施 Chunk 调整、查询表达、换模型或评测集修改。
- Chunk 调整会影响 P01 冻结的定位和 Final Chunk ID；查询表达或换模型会突破当前“唯一例外=本地
  Reranker”；修改评测集会改变 AV1-P02 Ground Truth，并需重新冻结门槛 `1.0`。三者均属于产品/范围
  决策，必须重新授权。
