## 1. 摘要

按"召回缺失 → 无据高分"顺序制定两阶段方案并完成实施。C4-A（Top-30 候选池）和 C4-B（仅 Reranker 查询表达）均已完成真实固定集复验，质量门槛未通过。

### 固定不变量

- AV1-P02 固定 12 题不变；
- 使用健康本机 `8000`，不启动 `8002`；
- 保留 Final Chunk、定位、引用和项目隔离；
- 公开接口最多返回 `top_k ≤ 10` 条；
- 不提前冻结任何阈值；
- 不引入 BM25、混合检索、远程 Rerank、跨项目检索或无授权的 Chunk 修改；
- 引用继续使用原始 Final Chunk 的正文、文件名、定位和 Chunk ID。

### 当前问题根因（从问题分析台账提取）

**问题 1：召回缺失（Chroma 层面）**

`GROUNDED-01 / GROUNDED-05 / GROUNDED-07` 的标准证据在 Chroma 完整 Top-20 中均未出现，不是 Reranker 将其排下去的。三次独立实验结论一致：

| 阶段 | Top-N | 标准证据进 Top-N | 无据 2/2 | 隔离 2/2 |
|---|---|---|---|---|
| C.3-A 内部 Top-20 诊断 | 20 | `GROUNDED-01/05/07` 未进 | 否（全漏） | 是 |
| C.3-B values 复验 | 20 | 同上 | 否（全漏） | 是 |
| C.3-C 查询表达复验 | 20 | 同上 | 否（全漏） | 是 |

**问题 2：无据高分不可分（Reranker 层面）**

C.3-C 用前缀模板 `档案证据检索问题：{query}` 做过一次查询表达复验，无据分数几乎没变：

| 阶段 | 无据题 1 最高分 | 无据题 2 最高分 | 变化幅度 |
|---|---|---|---|
| C.3-B（values，无前缀） | 0.981258 | 0.696090 | — |
| C.3-C（`档案证据检索问题：`） | 0.973935 | 0.707142 | < 1% |

前缀指令 + 原始问题这个模式对无据分离几乎没有改善。

## 2. 路由逻辑

```
C4-A：Top-20 → Top-30
  │
  ├─ 标准证据进 Top-30 < 7/8
  │     → 记录召回缺失 + 具体未进题目 + 停止
  │
  ├─ 标准证据进 Top-30 ≥ 7/8
  │     │  诊断：对比 Top-20 无据基线 + P95 + 具体未进题目
  │     │
  │     ├─ 同时：无据 2/2 + 隔离 2/2
  │     │     → 跳过 C4-B，直接 C4-C 阈值标定
  │     │
  │     └─ 无据拒答仍不足 2/2
  │           → C4-B（只改 Reranker 查询表达，Embedding 不动）
  │
  └─ 出现越权候选
        → 停止并修复授权范围

C4-B：只修改 Reranker 查询表达
  ├─ Embedding 查询 = C4-A 基线（不动）
  ├─ Reranker 查询 = "请从项目档案中查找与问题直接匹配的原文证据：{query}"
  ├─ 诊断：无据分数 + P95 + 隔离
  └─ 未达标 → 记录无据分离失败，停止

C4-C：仅三项门槛同时通过后标定阈值
  └─ 标定 archive_reranker_score_threshold
```

## 3. C4-A：Top-30 召回实验

### 实验变量

仅修改 Chroma 交给本地 `BAAI/bge-reranker-base` 的内部候选数：

- Chroma `n_results` 固定为 **30**；
- 授权校验和元数据过滤（`user_id + project_id + kb_id + document_id`）不变；
- Reranker 仍只接收授权校验后的候选；
- **不改变**公开 `top_k ≤ 10`、Chunk、Embedding 查询表达、Reranker 模型和评测集。

### 验收重点

| 验收项 | 通过条件 | 不达标处理 |
|---|---|---|
| 有据召回 | ≥ 7/8 标准证据进入内部 Top-30 | < 7/8 → 记录召回缺失 + 具体未进题目 + 停止 |
| 无据拒答 | 2/2（仅作观察，不阻塞进入 C4-B） | 不足 → 允许进入 C4-B |
| 项目隔离 | 2/2 | 出现越权 → 停止，修授权范围 |
| P95 延迟 | 记录，15s 作为风险提示 | 不新增为 P14 质量门槛 |
| 候选完整性 | 记录 `candidate_count` | 候选不足 30 → 只记录"候选池不完整"，不得断言召回失败 |

### C4-A 路由决策补充

- 即使 ≥ 7/8 达标，也必须记录**哪几题的标准证据未进入 Top-30**；
- 如果 Top-30 让无据最高分反而上涨（超过 C.3-B 基线 0.981258 / 0.696090），需在诊断中标注"扩大候选池恶化无据分离"；
- C4-A 完成后，固定集运行器应安全输出完整 Top-30 的 dense 排名和 Reranker 排名，供后续决策参考。

### 实际实验结果（2026-09-02，质量未通过）

| 指标 | 结果 |
|---|---|
| 候选池完整性 | 12/12（每题 Chroma 与范围校验后均为 30） |
| 公开覆盖式召回 | **7/8**（达到门槛 ≥7/8） |
| 严格诊断召回 | **5/8** |
| 未命中题目 | `GROUNDED-07`：两种语义均未命中；`GROUNDED-01/05`：公开覆盖命中但严格语义未命中 |
| 无据拒答 | 0/2 |
| 项目隔离 | 2/2 |
| 无据最高分 | 0.973935、0.707142 |
| 相对 Top-20 基线差值 | 分数变化 = 0、dense distance 变化 = 0 |
| P95 延迟 | 1819.88 ms |
| 清理 | PostgreSQL、Chroma、临时账号/会话/知识库/项目/文档/快照均为零 |
| 代码回归 | 定向 50 passed；全量 273 passed, 2 skipped；compileall 通过 |

**已证实结论**：
- Top-30 没有改变无据最高分（差值 0），说明扩大候选池对无据分离无改善；
- `GROUNDED-07` 两种语义均未命中，证实该题在 Top-30 下仍存在召回缺失；
- `GROUNDED-01/05` 属于**匹配语义不一致**（公开 Chunk 覆盖匹配到了，但严格文件+定位+摘录精确匹配未通过），不应直接归因为召回缺失；
- 公开覆盖式召回已达到 7/8，按路由逻辑可以进入 C4-B。

完整诊断见 [检索质量问题分析与改进策略.md](检索质量问题分析与改进策略.md) §13。

## 4. C4-B：Reranker 查询表达复验（低优先级）

### 优先级说明

C4-B 被标记为**低优先级验证实验**，原因：

- C.3-C 已用类似结构（前缀指令 + 原始问题）做过一次复验，无据分数变化 < 1%；
- 只有 C4-A 已确认召回 ≥ 7/8 且无据分离仍不足 2/2 时才执行；
- 若 C4-A 本身三项全过，C4-B 直接跳过。

### 实验变量

**仅修改 Reranker 侧查询表达**：

- Reranker 查询：`"请从项目档案中查找与问题直接匹配的原文证据：{query}"`；
- **Embedding 查询保持 C4-A 基线不变**（当前 C.3-C 状态：`为这个句子生成表示以用于检索相关文章：档案证据检索问题：{query}`）；
- 不使用 LLM 改写、查询扩展或多模板；
- 不更换模型、Chunk、候选池或评测集；
- 只允许一次固定表达复验。

### 实现约束：Embedding / Reranker 查询拆分

C4-B **不能继续复用当前同时服务 Embedding 和 Reranker 的查询构造函数**，必须拆成两套：

```text
build_query_for_embedding()  →  保持 C4-A 基线不变
build_query_for_reranker_v2() →  新建，使用固定表达
```

否则仍会改变 Chroma 候选集，无法证明变化来自 Reranker 查询。

### 验收

```text
有据命中 >= 7/8
无据拒答 = 2/2
项目隔离 = 2/2
```

若仍未通过，只记录"无据分离失败"，不得自动更换模型、再次修改查询或降低门槛。

### 实际实验结果（2026-09-02，质量未通过）

| 指标 | 结果 |
|---|---|
| 候选池完整性 | 12/12（每题 Chroma 与范围校验后均为 30） |
| Embedding 查询 | 保持 C4-A 基线不变（Embedding/Reranker 查询已拆分） |
| Reranker 查询模式 | `c4_b`（固定表达 `请从项目档案中查找与问题直接匹配的原文证据：{query}`） |
| 公开覆盖式召回 | **7/8** |
| 严格诊断召回 | **5/8** |
| 未命中题目 | `GROUNDED-07`：两种语义均未命中；`GROUNDED-01/05`：匹配语义不一致（同 C4-A） |
| 无据拒答 | 0/2 |
| 项目隔离 | 2/2 |
| 无据最高分 | **0.986686**、**0.952463** |
| 相对 Top-20 基线分数变化 | **+0.012751**、**+0.245321**（显著上升） |
| dense distance 变化 | 0（召回侧未受影响，确认变量隔离） |
| P95 延迟 | 3765.54 ms |
| 清理 | PostgreSQL、Chroma、临时账号/会话/知识库/项目/文档/快照均为零 |
| 代码回归 | 定向 47 passed；全量 275 passed, 2 skipped；compileall 通过 |

**已证实结论**：
- C4-B 的变量隔离成功：Embedding 查询未变 → dense distance 与 C4-A 完全一致 → `GROUNDED-07` 的召回缺失与本次 Reranker 查询变更无关；
- Reranker 新查询表达**不但没有改善无据分离，反而让无据最高分上升**（第二无据题从 0.707 跃升至 0.952，+0.245）；
- 公开覆盖式召回仍为 7/8、严格诊断仍为 5/8，C4-B 没有带来任何召回改善；
- 当前固定模板已完成一次受控复验，不得自动重复查询表达实验。

完整诊断见 [检索质量问题分析与改进策略.md](检索质量问题分析与改进策略.md) §14。

## 11. C4 阶段结论

### 11.1 实验总结

| 阶段 | 变量 | 严格召回 | 无据最高分 | P95 | 结果 |
|---|---|---|---|---|---|
| C.3-C 基线 | Top-20 + 固定查询表达 | 5/8 | 0.973935 / 0.707142 | 3791ms | 质量未通过 |
| **C4-A** | Top-30 | **5/8** | 0.973935 / 0.707142（差值 0） | 1820ms | 质量未通过 |
| **C4-B** | Top-30 + 仅 Reranker 新查询 | **5/8** | **0.986686 / 0.952463（显著恶化）** | 3766ms | 质量未通过 |

### 11.2 已证实的事实（仅限当前配置、当前固定集）

**事实 1：`GROUNDED-07` 在当前配置下 dense 召回缺失**

GROUNDED-07 的标准证据在 Top-10、Top-20 和 Top-30 中均未被 Chroma 召回。扩大候选池到 Top-30 对它没有任何帮助——说明在当前 Embedding（bge-small-zh-v1.5）、当前查询表达和当前 Final Chunk 表示下，它的 dense distance 排在前 30 名之外，或者根本不在 63 个 Final Chunk 里。

**尚不能断言**这是 BGE Embedding 模型语义能力的唯一根因——Chunk 表示粒度、问题与标准证据的语义对齐方式也仍是可能因素。

**事实 2：当前 base Reranker 在当前候选集上无可冻结阈值**

两个无据题在所有实验中都产生了 ≥0.69 的 Reranker 最高分。C4-B 换了 Reranker 查询表达后反而让无据分数恶化（第二题从 0.707 → 0.952）。在当前 BGE-small-zh Embedding 生成的 Top-30 候选集上，BAAI/bge-reranker-base 配合这一条固定模板无法产生可冻结阈值。

**尚不能推广**为该模型在所有候选集或所有查询表达下都无法区分真相关与伪相关——不同 Embedding、不同候选池、不同 Reranker 模型可能有不同表现。

**事实 3：`GROUNDED-01/05` 是匹配语义差异，不是召回缺失**

公开覆盖式召回为 7/8 但严格诊断只有 5/8。GROUNDED-01/05 在公开 Chunk 覆盖匹配中被算作命中，但在文件+定位+摘录精确匹配中失败。这是匹配语义差异，不应归因为召回缺失。

### 11.3 观测上限（仅限当前配置、当前固定集）

在 bge-small-zh-v1.5 Embedding + BAAI/bge-reranker-base Reranker + Final Chunk + AV1-P02 固定集的组合下，**观测到**严格召回上限为 **5/8**（GROUNDED-01/05/07 三题），无据拒答上限为 **0/2**。

**不推广为该模型组合的普遍硬天花板**——更换 Embedding 模型、更换 Reranker 模型、调整 Chunk 粒度或引入混合检索都可能改变这个结果。
