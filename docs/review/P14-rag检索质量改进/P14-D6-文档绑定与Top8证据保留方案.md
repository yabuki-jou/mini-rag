### 1.3 文档与代码差异

D5 方案第 3.1 节要求“提示中的文件名、定位和摘录由服务端组装”，但实际 `app/services/archive_question_service.py` 的 `_build_archive_prompt()` 只接收 `list[str]`，调用处只传 `[item.excerpt ...]`。

结果是模型只能看到 `[S1] 摘录`：

- 看不到候选属于哪个文件；
- 无法把同一文档的标题 Chunk 和字段值 Chunk 绑定；
- 面对多个文档都有 `版本号：V1.0` 时，不能判断哪个值属于问题中的目标文档。

这是实际代码与已确认 D5 方案的不一致。以实际代码为准记录结果，但后续实现应先修复该差异并独立验证。

## 2. D6-A：仅增加文档绑定信息

### 2.1 唯一变量

只改变进入 DeepSeek 的证据表示，不改变候选集合或排序：

```text
[S1]
document_ref: D1
filename: beta_design_spec.md
location: TEXT_LINE_RANGE 2-2
excerpt: 资料标题：云港仓储中心设计技术说明
```

- 同一 `document_id` 在一次请求内映射为相同的临时 `document_ref`（`D1`、`D2`……）。
- `document_ref` 仅用于本次提示，不返回客户端、不持久化、不暴露真实 UUID。
- 文件名、定位和摘录只取自已通过服务端正式范围校验的 `ArchiveRetrievalItemRead`，模型不能覆盖。
- Top-5、Top-30、排序、分数、模型、查询和固定集全部保持不变。

### 2.2 TDD 计划

RED：

1. 同一文档的两个候选必须获得相同 `document_ref`，不同文档必须不同。
2. 提示必须包含服务端文件名、定位类型/起止和摘录。
3. 提示不得包含原始 `document_id`、用户/项目/知识库 ID。
4. 证据文本中的伪指令仍只能作为数据，不能改变 JSON 协议。
5. 原有空候选短路、严格 JSON、引用编号校验和外部响应契约测试保持通过。

GREEN：只把 `_build_archive_prompt()` 的输入从纯摘录扩展为已校验候选，并生成请求内文档引用；不修改检索服务。

### 2.3 D6-A 验证门

- 先使用 D5 已捕获 Top-5 数据复跑同一 12 题，完成独立 Pixie Step 6。
- 安全门：无据 `2/2`、隔离 `2/2` 不得下降；Q-07 不得继续引用其他文档的版本号。
- D6-A 不要求 Q-02/Q-07 回答正确，因为正确值仍不在 Top-5；若由错误回答转为拒答，视为安全改善但不视为 P12 通过。

## 3. D6-B：仅将问答候选从 Top-5 扩大到 Top-8

### 3.1 进入条件

只有 D6-A 安全门通过并完成清理、分析后，才能单独授权 D6-B。

### 3.2 唯一变量

- `archive_question_service.py` 调用正式检索的 `top_k` 从 `5` 改为 `8`。
- 文档绑定使用 D6-A 已验证表示；除此之外不改 Prompt 指令、模型、Embedding、Reranker、Top-30、Chunk、查询表达、固定集或门槛。
- 公开检索接口仍保持 `top_k≤10`；问答接口响应仍只返回模型选中的引用，不自动返回 8 条候选。

选择 `8` 而不是 `10` 或 `30` 的依据仅是当前固定快照中 Q-02 目标证据位于第 8、Q-07 位于第 6；这是最小覆盖边界，不代表更大数据集的通用最佳值。

### 3.3 TDD 与风险

RED：

1. 问答检索明确请求 `top_k=8`，其余参数不变。
2. 只返回模型声明编号对应的引用，编号上限随实际候选数校验。
3. 无据题即使增加候选仍必须固定拒答且引用为空。
4. 文档绑定必须保证标题/字段值可按同一 `document_ref` 关联，不能把其他文档相同字段名的值拼接到目标文档。

主要风险是候选增加会引入更多相近但错误字段。D6-A 必须先行，且 D6-B 仍需真实 DeepSeek 评估；单元测试不能证明语义质量。
