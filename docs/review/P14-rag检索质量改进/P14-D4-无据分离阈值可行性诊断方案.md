# P14-D4 无据分离阈值可行性诊断方案

## 1. 状态与纠偏

**状态：D4-A/D4-B 确定性代码与真实 base 快照/离线扫描已完成；large 尚未执行。** D3 的无据 `0/2` 是未启用阈值时的观测，不能单独证明所有统一阈值不可行；D4 base 已扫描全部实际分数边界并确认不存在可行统一阈值。large 链路 P95 `9512.28 ms` 仅作完整链路观测，是否继续生成 large 快照仍需用户结合延迟风险另行确认。

## 2. 目标与边界

判断是否存在单一全局 `reranker score threshold`，同时满足公开覆盖 `≥7/8`、无据拒答 `2/2`、项目隔离 `2/2`。D4 只记录可行性、阈值区间和余量，不写配置、不冻结阈值。严格命中 `6/8` 仅作诊断，不能替代公开覆盖门。D4 先判断阈值质量可行性；性能判定复用同测量口径的 D2 纯 Reranker 结果，完整链路 P95 单独记录。

冻结变量：`bge-base-zh-v1.5/768`、独立 Collection、`evidence_values`、Top-30、`c4_a`、AV1-P02 固定 12 题、公开 Top-10；模型之外不变。执行顺序调整为 **base 优先、large 条件执行**：先完成 base 快照和离线扫描；base 若存在可行阈值，本轮即可形成兼顾质量与既有性能证据的候选结论，不再自动运行 large；只有 base 不存在可行阈值且用户仍需要判断 large 的额外质量收益时，才另行执行 large 并核对同候选指纹。不得修改 `.env`、正式 Collection、Chunk/窗口、查询表达、评测集、BM25 或混合召回。

## 3. D4-A：安全分数快照

当前 D3 聚合诊断不足以进行阈值扫描。需在内存中对每题完整 Top-30 保存：candidate score、reranker rank、`category`、`case_id`、public coverage match bool、strict match bool、`candidate_kind`。禁止保存正文、真实 ID、文件路径和 Token；持久化仅保留脱敏布尔/数值及候选指纹。

`public coverage match` 必须复用现有验收语义。GROUNDED-01/05 不能因严格匹配语义不一致而被误判为召回失败。快照必须确认 12/12 候选完整、base/large 指纹一致；否则本轮无效。

实现采用仅开发环境可见的诊断投影：原始 Chunk ID 在服务端使用带固定域前缀的 SHA-256 转换为稳定 `candidate_key`；公开覆盖与固定集验收调用同一纯匹配函数；快照只写 `case_id`、类别、排名、分数、脱敏候选键和布尔/枚举标签。由于原有诊断响应没有稳定候选身份和逐候选公开覆盖标签，本步实际增加了开发诊断 Schema/Service 字段；公开检索 API、正式阈值和生产环境路由可见性均未改变。

## 4. D4-B：离线阈值扫描

复用或抽取 `scripts/archive_v1_p14_acceptance.py` 中 `score_reranker_outcomes` 与 `choose_reranker_score_threshold` 的思想：

1. 阈值候选来自实际唯一分数及其边界 `nextafter`，不按题设臆造阈值。
2. 按 `score >= threshold` 过滤，稳定排序后最多保留 Top-10。
3. 对每个阈值计算三项质量门、可行阈值集合、最宽松通过阈值（最低值）、`max_no_evidence_score`、grounded 保留余量和最小 margin。
4. 不按题设单独调题，不写入正式配置，不冻结阈值。

离线扫描器已实现输入白名单、精确 `8/2/2` 类别数量、每题 Top-30、rank/score 一致性、Top-10、`score >= threshold` 与 `nextafter` 边界、候选指纹/静态标签漂移、无据与隔离联合余量，以及失败输出清理。为落实 base 优先门控，CLI 还支持单模型快照扫描；base 真实分数已完成扫描，large 仍未扫描。

## 6. 决策表

| 结果 | 决策 |
|---|---|
| base 有可行阈值且性能通过（D2 纯 Reranker P95 `3520.995 ms`） | 建议单独授权 C4-C 正式标定 |
| large 有可行阈值但性能失败（D2 最佳参数纯 Reranker P95 `12016.218 ms`，>8000 ms） | 不正式切换，记录质量收益与成本；D3 完整链路 P95 `9512.28 ms` 仅作观测 |
| base/large 均无可行阈值 | 停止继续更换同类 Reranker，另行设计证据充分性/拒答判定层 |
| 候选指纹不一致或快照不完整 | 本轮无效，重新运行 |

不得根据表格自动进入任何分支。

当前执行门：先运行 base。large 不是 base 实验的并行必选项；base 无可行阈值也不会自动授权 large，仍需结合其已知延迟风险由用户确认是否继续。
