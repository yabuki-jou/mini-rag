# FR-042 本地后端闭环验收复盘

## 最终结论

真实后端闭环通过。验证使用本地 FastAPI、Chroma、BGE、Reranker、文件和 SQLite Checkpoint，
PostgreSQL 使用远端开发库中的随机隔离 Schema，模型使用真实 DeepSeek。测试资料完全虚构，未读取
现有用户档案。

## 三轮变化

| 轮次 | 结果 | 问题 | 优化 |
| --- | --- | --- | --- |
| 第一轮 | 不通过 | 验收脚本要求三轮必须恰好产生 3 条工具日志，超过了“每轮最多两次”的冻结契约 | 改为逐轮检查工具种类和 `1..2` 次预算 |
| 第二轮 | 不通过 | 无据题返回了合法的零工具固定拒答，脚本仍要求至少一次证据工具 | 按需求/API 的零工具拒答条款，把无据题预算改为 `0..2` |
| 第三轮 | 通过 | 无业务失败 | 保持目录和有据题必须调用正确工具；无据题允许零工具安全拒答 |

首次启动临时脚本还出现过项目导入根缺失；该错误发生在 Schema 创建和模型调用之前，修正
`sys.path` 后消失，不计为业务验收轮次。

## 通过证据

- 健康检查：PostgreSQL、Chroma、Embedding 全部正常。
- 随机隔离 Schema：从空 Schema 迁移到 `0011_archive_agent_scope`。
- 文档链路：上传、解析、人工字段确认、`CONFIRMED`、Chroma 正式索引全部完成。
- 助手链路：目录回答、有据回答和引用、无据固定拒答均通过。
- 会话链路：三组完整用户/助手历史；目录和证据工具各产生一条脱敏审计。
- 隐私：公开回答、历史和工具摘要未出现范围 UUID、文档/Chunk ID 或检索分数。
- 清理：PostgreSQL、Chroma、文件、Checkpoint 均为零残留，随机 Schema 已删除。

## 证据边界

- PostgreSQL 不是本机进程，而是项目当前配置的远端开发实例；只使用并删除随机隔离 Schema，未迁移
  或写入 `public` Schema。
