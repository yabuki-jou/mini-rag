## 1. 结论

文档整理方案方向合理，可以进入执行。执行时必须遵守以下边界：

- 前后端分别使用独立分支和独立提交。

- 后端接口设计仍是 API 契约的唯一事实源，前端文档只引用，不复制契约全文。
- 不移动进行中的 `P14-rag检索质量改进/` 和当前 `FR-042-*` 评审资料。
- 不暂存或修改与文档整理无关的代码文件。

## 5. Handoff 约束

后端当前超长 handoff 整体归档，前后端分别建立新的当前快照。新快照固定使用以下章节：

1. 当前分支与环境；
2. 已完成里程碑；
3. 未完成与待确认；
4. 已知风险；
5. 文档导航。

handoff 只保存当前状态，不继续累积全过程流水。

## 6. 执行与验证顺序

1. 前端建立目标目录并复制文档，补充溯源信息和精简 FR-042 接入记录。
2. 修复前端文档引用，建立前端 README 和 handoff。
3. 检查前端不存在失效路径，提交前端变更。
4. 前端迁移结果确认后，后端更新根 README、handoff 和相关引用。
5. 后端删除已迁出的重复文档，按白名单归档历史资料，并将验收报告归位。
6. 两个仓库分别运行路径检索、`git diff --check` 和 Git 状态检查。
7. 前端变更先合并，后端删除变更后合并。
