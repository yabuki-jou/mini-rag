## 1. 目标

在固定集保持不变的前提下，检验实际检索候选进入生产回答判定与引用映射后，答案事实、冻结目标证据、扩展来源支持及无据拒答是否符合各自口径。特别观察贷款问题的两种重排表达是否改变最终答案或引用，而不只看目标页是否进入 Top-8。

既有 LUSHAN-01 五组、15 次真实 DeepSeek 对照已经完成；C 组（双路并集由 `IBRD IDA` 表达重排）冻结页引用为 3/3。该结果单独引用，不并入本轮样本量，也不重跑 LUSHAN-01。

## 2. 边界

- 只评 FR-039 共享生产回答判定层 `answer_archive_question` / `judge_archive_answer` 及其引用映射；Pixie 通过现有 `ArchiveQuestionRunnable` 驱动，输入为实际检索生成的候选。
- 检索候选须来自重新建立的独立 P153548 与 Belarus 项目索引；既有脱敏检索 JSON 不含可重放摘录，不能代替候选输入。运行时不把摘录或模型回答写入 Git 跟踪文件。
- 本轮不评 FR-042 Graph 的工具选择、多轮行为或持久化；不验证尚未实现的世界银行贷款意图门控。正负路由字符串向量仅是后续门控 TDD 的依据。
- 不改 `app/`、正式配置、公开 API、冻结评估集或正式向量数据。必要的 Pixie 评测适配器、数据集和专用 evaluator 属于评测代码，须先按 TDD 验证并由主 Agent 审查。
- 任何 PostgreSQL/Chroma/文件/Checkpoint 写入都只允许在本次新建且预检为空的隔离目标内；执行前须重新取得用户对隔离资源和模型调用的明确授权。

## 4. 调用预算与执行纪律

- 最多 21 次真实 DeepSeek 回答判定：7 个条件组 × 3 次，放在一个可审查的 Pixie 数据集运行中；每条输入独立调用生产回答服务，不共享会话历史。
- 对贷款正例的两种条件按预先固定、交错的顺序执行，降低模型服务时段变化与顺序偏差；其余案例也按轮次交错执行。
- 每次客户端明确设置 `max_retries=0`。失败、超时或非法输出占用该次预算，不自动重跑；未完成结果按失败报告。21 是调用硬上限，不是必须调用数。
- 每个条件组报告 3 次逐次结果及中位数/通过数；三次观察仅描述本资料上的波动，不宣称统计显著性或泛化质量。
- 每个回答判定只调用一次模型；Embedding、Chroma 和 Reranker 不计入 DeepSeek 调用数，另行报告其调用次数与耗时。

## 5. 评分与记录

对每次运行分别记录：

1. `answer_status`、答案事实是否符合预期、是否正确拒答；
2. 引用是否来自本次实际候选、引用文件与 PDF 页码/范围；
3. 冻结目标证据是否命中；
4. 扩展来源是否经人工核验直接支持该回答中的实体、金额语义及时间口径；
5. 候选池完整性、Top-8 支持证据覆盖和所用排序表达；
6. 检索各阶段、Reranker、回答判定的调用数与逐次耗时。

冻结证据与扩展来源分开报告，严格遵循 DEC-024。引用不在冻结目标页时，不自动判失败，也不自动判通过；未逐条人工核验的替代来源标记 `needs_manual_review`。模型评分不得代替人工核验原始 PDF 页面和被引摘录是否语义支持答案。

执行前冻结以下样例级判定，不跨案例平均：三个有据案例 `LUSHAN-02/03`、`WB-REV-LOAN-01` 两种条件和 `WB-CONTEXT-NONLOAN-01`，各自均须在三次中 3/3 答案事实正确且引用支持答案；两个否定案例须各自 3/3 固定拒答且无引用。任一案例未达到该门槛就如实记为未通过，不调低阈值；人工来源核验未完成时标为待复核，不计支持通过。每个正向条件在调用前还须确认 Top-8 含人工核实的支持证据，否则记检索前置条件失败并跳过该组模型调用，避免把检索遗漏误判成回答能力。

回答事实、引用映射及拒答使用项目 evaluator 的确定性检查；模型回答本身以真实生产模型生成。Pixie 完整执行后完成 Step 6 的逐条结果分析、汇总和行动计划。Pixie 的离线自评分不作为人工来源支持的替代证据。

## 8. 实际回答/引用评测结果与后续边界

### 8.1 执行与恢复

- 在隔离资源准备通过后，Pixie 单数据集命令运行约 30.1 秒、退出码 1；包装器为避免输出原始 Trace/回答而抑制了 CLI 文本，但未先保存白名单失败阶段，因此具体异常无法还原。结果目录有 21 条 entry Trace、21 条最终响应记录，没有正常 `meta.json` 或评分文件。
- Trace 审计显示每条样本有一个最终响应；每条出现两条输入/输出哈希相同的 LLM span 记录。结合生产服务每个样本唯一一次 `.invoke`、`max_retries=0`、21 个最终响应及零错误 span，确认本批实际调用 21/21，不是 42 次。调用预算已耗尽，不重跑。
- 新增结果文件仅由原数据集与保存的 Trace 配对重建；21/21 检索输入与注入数据逐项完全相同，确定性 evaluator 无 LLM 调用。使用 Pixie `save_test_result` 写入正常结果结构，并在 `meta.json` command 字段声明离线重建及 CLI 失败；21 条评分可重载、pending 为 0，Trace 均保留。故这不是原生 Pixie CLI 成功，不掩盖其退出码。

### 8.3 结论边界与下一步

- `WB-UNSUPPORTED-DRAW-01` 的 0/3 是真实拒答质量失败：第 16 页只记录截至 2015-03-05 的表格值，其中 `Amount=250`、`Disbursed=0`；问题问当前或完工时实际提款，Trace 却回答 250 million。当前证据不支持这个时间口径，应拒答。
- LUSHAN-03 的严格冻结页门仍为 0/3：冻结目标第 20 页在 Prompt 第 5 位，模型选择第 14 页；但第 14 页同一份 IEG Review 明确给出 Outcome Rating Satisfactory，语义上支持答案。因此这是冻结页未命中，不应描述成答案或引用语义错误。
- 补充表达重排组的机械答案契约为 0/3，因为三种回答都没有字面包含期望子串 `US$250 million`；人工核验确认它们均表达 250 百万美元，且引用第 16 页直接支持。该组结果不能作为事实退化证据。单一资料的三次样本也不足以形成通用排序或融合结论。
- 无据提款组的引用确实能映射到候选，但现有 evaluator 对预期拒答样本把 `citation_mapping_passed` 设为 `not citations`，再优先给出 `CITATION_NOT_IN_CANDIDATES`；该错误码把“拒答时仍有引用”误标成“引用不在候选”。总分仍因回答未拒绝且附带引用而为 0。
- P14 冻结集未修改；未改生产检索、回答 API、正式配置或用户资料。任何后续 TDD 生产实现须先单独形成并确认实施计划；增加真实模型调用须另获预算授权。

### 8.4 离线语义复核与错误排查记录

- 仅复核已有 Trace 和本地固定资料 PDF，没有新增模型调用或修改应用代码。实际检查了 9 条扩展目标页引用：贷款问题原问题重排 3 条、补充表达重排 3 条、非贷款上下文 3 条；均定位 Belarus Snapshot 第 16 页。PDF 表格列明 IBRD Loan Amount 250、Disbursed 0、Undisbursed 250，来源截至 2015-03-05；同页正文明确 Bruzgi 口岸预计处理量从 700 提高至每日 1,700 辆。因此贷款金额与非贷款容量两个问法均由对应正文/表格直接支持。
- 同一批另有 1 条额外引用至第 7 页。原 PDF 在该页将 M6 Transit Corridor Improvement 项目标为 US$250 million；它支持项目金额，和第 16 页的 IBRD 贷款表格互补，不计入原定 9 条目标页引用统计。
