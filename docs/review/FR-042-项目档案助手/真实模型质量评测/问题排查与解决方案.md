# FR-042 不合格问题排查与解决方案

## 排查顺序

1. **检查工具路径**：事实问题是否只调用一次证据工具；目录问题是否只调用目录工具。
2. **检查候选事实**：正确答案是否真实出现在当轮安全候选中。
3. **检查文档身份**：用户提到的文档是否能由候选中的标题、显示名或文件名识别。
4. **检查同文档绑定**：文档身份与字段事实是否属于同一个 `document_ref`，不能跨文档拼接。
5. **检查判定结果**：事实、身份和绑定都充分时才把错误拒答归为应用问题。
6. **检查评估器**：逐轮评分，任一核心轮失败都不能被平均分掩盖。

## 解决方案

1. 在需求/API/数据设计中明确：是否把已确认档案的稳定标题或显示名作为模型可见候选字段。
2. 标题只能来自可追溯的正式元数据或原文，且必须与字段候选共享 `document_ref`。
3. 为数据构建增加硬门：应回答场景必须同时具备目标文档身份和答案事实，否则禁止生成。
4. 如果原资料没有标题证据，则重新捕获合法候选，或把场景改成身份不足拒答；不得伪造资料。
5. 契约确认后按 TDD：先写身份绑定正例、跨文档负例和无身份拒答测试，再做最小修改。
6. 相关测试、FR-039 回归、全量测试和 `compileall` 通过后，再申请一次真实 DeepSeek 定向回归。
