# P153548 融合候选进入回答与引用链路的隔离对照计划

> 状态：实验设计与真实模型对照均已完成；结果已写入排查报告，未据此授权正式实现。
>
> 对应问题：FR-039 / FR-042 使用 P153548 公开资料时，`LUSHAN-01` 的贷款金额证据在双路候选融合后进入 Top-8，但用户可见回答与引用尚未验证。
>
> 依据：本项目固定 P153548 资料、`docs/review/FR-042-项目档案助手/P153548真实资料召回问题排查与解决方案.md` 第 7.7 节、当前 `app/services/archive/questions.py` 与 `app/services/archive/retrieval.py`。本计划不改变冻结标注、正式检索策略或产品接口。

## 1. 要回答的问题

在同一批真实 Chroma / `evidence_values` 已确认档案上，给回答模型提供不同排序的 Top-8 后，`LUSHAN-01` 的回答事实与引用是否改善？改进是只发生在候选覆盖，还是能到达最终引用？

上次隔离验收两路各取 dense Top-30，交集 15、并集 45；在并集上原问题重排的公开证据覆盖排名 22，补充表达重排第 3，RRF `k=10` 第 7，min-max 等权第 6。上次脱敏 JSON 不保存 Chunk ID、原文或完整候选，因此不能用于直接重放模型输入。本次须重新建立**独立**隔离索引，并在清理之前完成候选与回答对照。45/15 是上次观测值，不预设本次必须完全相同；若数量不同，要记录并核查资料、配置和候选构造，不能静默套用旧排名。

## 2. 固定输入与比较组

- 仅使用已核对 SHA256 的四份 P153548 PDF，以及冻结集 `LUSHAN-01` 的原始中文问题和现有标准证据。向量化、确认字段、Chunk 切分、模型配置及项目范围由同一次隔离验收固定。
- 补充检索表达只把原问题中的一次“世界银行”替换为 `IBRD IDA`。两路各取当前正式配置的 dense Top-30，经过相同的 PostgreSQL 正式状态与 Chroma 元数据范围校验，按 `chunk_id` 去重，不截断候选并集。
- 所有组都以**用户原问题**调用现有 `judge_archive_answer`，使用同一份正式候选 DTO 和相同的真实模型、温度、超时配置；只有候选集/顺序不同。实验客户端明确设置 `max_retries=0`，使调用上限可以核算，这一点需与生产无参客户端的默认隐藏重试区别记录。引用编号按生产 `answer_archive_question` 的 `citation_numbers → candidates[number-1]` 规则映射。实验只调用公共判定层，不声称融合策略已经接入 FR-039 路由或 FR-042 Graph。

| 组别 | 回答模型看到的 Top-8 | 作用 |
| --- | --- | --- |
| A：正式单路基线 | 原问题 dense Top-30 经原问题重排 | 与当前 FR-039 候选入口核对 |
| B：并集原问题重排 | 两路并集经原问题重排 | 单独观察增加候选池的影响 |
| C：并集补充表达重排 | 两路并集经 `IBRD IDA` 重排 | 观察目标证据靠前时的表现 |
| D：并集 RRF | 同一并集两次重排，RRF `k=10` | 探索性融合对照 |
| E：并集 min-max | 同一并集两次重排，各自 min-max 后等权 | 探索性融合对照 |

A 组排序必须与同环境的 `retrieve_archive_answer_candidates(..., observe_result=False)` 返回的 `chunk_id` 顺序一致，否则停止模型调用并排查基线构造。B～E 的重排分数、次序和并列裁决使用前次诊断的确定性规则；五组均先记录 Top-8 公开证据覆盖、精确标准摘录匹配、文件与页码的脱敏摘要，再调用模型。

## 3. 模型次数、耗时和成本口径

- 五组各运行 3 次，共最多 **15 次真实 DeepSeek 判定调用**。执行顺序固定为第 1 轮 A/B/C/D/E、第 2 轮 C/D/E/A/B、第 3 轮 E/A/B/C/D。单次 JSON 错误或依赖失败记为该次失败，不自动补跑或扩大调用上限。模型配置与问题固定；3 次只能观察本资料上的波动，不提供统计显著性或泛化结论。
- 分别记录每次模型调用的墙钟耗时和各组中位数；检索、两路重排、融合后处理耗时分段记录，不把旧的内存候选计时算入本次正式 Chroma 链路。实验可用只转发 `invoke` 的请求内观测包装读取模型返回的 token 使用元数据，原始模型响应仍交给公共判定层；客户端若未返回用量则标为“未知”，不能估算成确定费用。
- 执行成本上限以 **15 次模型调用** 约束。正式运行前先生成 5 组 Prompt 并记录字符数、候选数和预计调用次数，供用户核对；不打印 Prompt、证据正文、密钥或 `.env`。金额费用需按当时实际模型账单单价和真实 token 用量计算，本计划不固定价格。达到调用上限即停止。

## 4. 判定与报告

每次记录回答状态、固定答案片段 `US$300 million` 是否出现、引用是否非空且编号有效，以及以下两种不同口径：

1. **冻结标注口径**：回答为 `ANSWERED`、含固定答案片段，并引用 2016 appraisal document 第 16 页的合格原文。固定集本身不改；精确标准摘录匹配与正式的公开证据范围覆盖分别列出。
2. **来源支持口径**：答案表达原批准/承诺贷款 `US$300 million`（允许仅格式不同），且被实际引用的原文摘录支持该事实。2016 appraisal 第 1/16 页、2022 restructuring 第 4 页、2024 completion report 和 completion review 第 1 页只作为**待逐条核对的来源候选**，不能仅凭文件名/页码自动判通过。实际提款约 `US$296.83 million` 不等同于原批准金额。若无法从该次引用摘录确认金额和语义，标记“待人工复核”，不得记为通过。

报告逐组列出 3 次状态、两种口径通过数、被引用的公开文件名与页码、模型耗时和 token 用量；保留失败和不确定结果。候选 Top-8 覆盖、模型是否正确回答、引用是否支持答案要分别报告。即使某组在三次中全部通过，仍只算 P153548 Q1 的探索性证据；不据此确定正式融合规则、通用 K、延迟预算或 FR-042 质量门。

## 5. 实施、TDD 与隔离

1. 仅扩展 `scripts/archive_lushan_persistence_acceptance.py` 及对应 `tests/scripts/` 测试，增加显式的融合回答对照模式。该模式复用资料确认和双路检索步骤，但**跳过既有验收脚本的 FR-039/FR-042 模型轮次**，使整次运行的 DeepSeek 请求总上限仍为 15。先写并实际运行失败测试：五组排序与基线一致性、相同并集和原问题传入判定层、引用编号映射、结果脱敏、15 次上限，以及发生模型异常时仍执行跨层清理。随后最小实现并运行定向、全量测试与 `compileall`；由主 Agent 审查差异。不改 `app/`、Vue、冻结数据集、正式配置或公开 API。
2. 每次运行使用随机临时 PostgreSQL Schema（连接 `search_path` 固定到该 Schema）、现有配置 tenant 下独立 Chroma 数据库和 Collection、独立文件、Checkpoint、日志路径。写入前确认全部目标为空且名称不碰正式默认资源。通过本地回环 API 执行 Alembic、真实四 PDF 上传/解析/人工确认/索引；候选与回答只在该临时范围内处理。
3. 即使测试失败，也停止临时 API，并逐层核对 PostgreSQL 业务行、Chroma 条目、文件、Checkpoint 为零；本模式预计不会写入 Checkpoint，应核对其始终为空。删除本次创建的精确 Schema、Collection/数据库和临时目录，再确认不存在。只把不含 UUID、Token、原文、Prompt、回答正文和引用摘录的聚合结果写入 `tests/pytest_docs/public_projects/lushan_earthquake_p153548/acceptance/` 的 Git 忽略文件。清理失败必须显式报错，不把质量结果标为完成。
4. 用本次真实结果更新 FR-042 排查记录和 `docs/stage/handoff.md`。若融合候选进入 Top-8 但答案或引用仍失败，定位到回答判定/候选质量环节并停止正式实现方案；若 Q1 表现改善，再单独评审反向正例、其他有据题、无据拒答、FR-042 Graph 与正式固定集回归，之后才收敛实现参数。

## 6. 本阶段的停止点

本计划先交付可审查的比较口径。真实执行已在用户授权的隔离资源中完成，新增 DeepSeek 调用实际为 15 次，未超过上限；公开 PDF 只作为本次固定资料输入，没有把 Prompt、回答正文、原文摘录、UUID、Token 或密钥写入结果文件。隔离 PostgreSQL Schema、Chroma 数据库/Collection、文件和 Checkpoint 均已核对清理。结果只覆盖 P153548 的 `LUSHAN-01` 单题，不能据此确定正式融合规则、通用候选上限、延迟预算或 FR-042 质量门。
