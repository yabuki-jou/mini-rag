# 实施前修订补丁 2(rev2→rev3 增量修订)

> **基础**:`设计基线补丁2-修订2.md`(最终应用版)
> **说明**:本文件为 3 处增量修订,应用后 rev2 无 `VERSION_CONFLICT` 过度使用、checklist-items 响应闭环、`expected_version` 表述收窄。
> **用法**:按以下 3 处替换 rev2 中对应段落,即可得到 rev3 完整效果。

---

## Δ1:补丁 3 中 suggestions/regenerate 的冲突分类(区分错误码)

**位置**:rev2 补丁 3 末尾「⊿ suggestions/regenerate」段落

**替换为**:

```text
- ⊿ `suggestions/regenerate` 必须携带 `expected_version`（文档当前版本），
  服务分两阶段校验，使用不同错误码区分冲突类型：
  1. 请求到达时：若已存在人工字段或人工证据（`review_status` 非全部
     `PENDING_CHECK` 或含 `source = MANUAL` 值/证据），立即返回
     `409 SUGGESTION_WOULD_OVERWRITE_MANUAL_DRAFT`，不调用模型。
  2. 模型调用返回后、事务内：再次校验版本与人工内容。
     - 版本已变（被并发修改）→ `409 VERSION_CONFLICT`；
     - 版本未变但人工内容不满足保护条件 →
       `409 SUGGESTION_WOULD_OVERWRITE_MANUAL_DRAFT`。
  不满足时均不替换草稿、不递增版本、不改变状态；满足时原子替换并版本 +1。
```

---

## Δ2:补丁 1.2b 中 POST checklist-items 响应补充新项目版本

**位置**:rev2 补丁 1.2b「POST checklist-items Schema 修订」末尾

**在规则"创建成功后 `projects.version` 原子 +1"之后追加**:

```text
`POST /checklist-items` 的 `201` 响应必须同时返回新清单项与新的项目版本，
客户端后续调用创建接口时使用 `project_version` 作为 `expected_project_version`：

{
  "item": {
    "id": "uuid",
    "name": "施工方案",
    "document_type": "CONSTRUCTION",
    "is_required": true,
    "project_stage": "CONSTRUCTION",
    "description": "每个施工阶段至少一份",
    "fulfillment_status": "MISSING",
    "confirmed_document_count": 0,
    "version": 1
  },
  "project_version": 2
}
```

## Δ3:补丁 3 中"客户端后续写操作"表述收窄

**位置**:rev2 补丁 3 第二条规则(版本递增后)

**将**:

```text
- 每次递增后，响应 `ProcessDocument.version` 必须返回最新值；客户端后续写操作
  必须携带该最新 `expected_version`，否则返回 `409 VERSION_CONFLICT`。
```

**替换为**:

```text
- 每次递增后，响应中返回最新版本值（`ProcessDocument.version` 或
  `project_version`）。所有声明 `expected_version` 或 `expected_project_version`
  的接口必须携带最新值，否则返回 `409 VERSION_CONFLICT`。
```
