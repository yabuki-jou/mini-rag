### 2.3 共同工程约束

- 保持 `Router → Application Service → Domain Service → 存储/外部依赖` 分层；不增加空转 Repository 层。
- 每个受保护接口从已验证 Bearer Access Token 建立当前用户与 `ProjectContext`；客户端和模型不能
  提交或覆盖所有者、项目/知识库范围，也不再接受 `X-User-ID`。密码、Refresh Token 明文和
  Token 负载不得写入审计或日志。
- PostgreSQL 是业务事实来源，原文件与解析快照位于文件系统，Chroma 只保存可重建的正式 Chunk；
  Compose 内 API 经内部 `chroma:8000` 访问。仅本地开发时可额外映射 `127.0.0.1:8001` 供宿主机
  Python 调试，局域网和公网不可访问。云端是否部署及其端口策略暂定至 V1 完成后。
- 未确认、待重新确认及 `visibility_blocking` 删除中的档案，均不得进入正式目录、检索或问答。
- 普通自动测试不调用真实 DeepSeek；外部模型只使用虚构或脱敏资料。旧 RAG/Agent 测试必须继续通过或明确说明其环境依赖。
- 不实现标书投标、OCR、Excel、跨项目检索、前端、多角色、混合检索、Rerank、任务队列或知识图谱。

## 4. 分任务计划

### AV1-P01 Parser 可行性验证与规则冻结（已完成，2026-08-06）

**目标与范围**

- 验证 PDF 页码、DOCX 段落序号、TXT/MD 行号范围均从 1 开始；DOCX 同时产生规范化段落文本前 50 字的辅助定位。
- 已固定 UTF-8 解码、换行归一化、空白归一化、表格/编号列表处理、有效文本最小字符阈值与最大解析文本量，详见 `docs/archive-v1-parser-design.md`。
- 使用同一原文件重复解析，确认定位和快照哈希可重复生成；扫描 PDF 或空壳文件必须得到 `PARSE_FAILED` 对应的稳定失败分类。

**明确不做**

- 不创建 `projects`、`archive_documents`、`parsed_snapshots` 等正式迁移或模型。
- 不注册归档 Router，不调用 DeepSeek/Chroma，不改写现有 `documents` 业务状态。

**预期改动范围（执行时再确认）**

- `app/services/archive_parser_service.py`（归档专用隔离适配器，未接入旧 RAG Parser）；
- `tests/services/test_archive_parser_service.py`（运行时动态生成虚构样本）；
- `docs/archive-v1-parser-design.md`（冻结规则与实际结果）。

**验证与完成条件**

1. 固定样本的 PDF/DOCX/TXT/MD 各至少一份解析成功；定位类型和值满足需求 §7.6。
2. 同一文件重复执行的 `ParsedFragment` 顺序、定位和 `snapshot_hash` 一致。
3. 无可提取文本 PDF 返回扫描件/无文本的受控失败分类，不被误判为成功。
4. 空壳文本被有效文本阈值过滤；阈值和规范化规则写入 Parser 设计说明。
5. 本任务相关测试和 `python -m compileall -q app tests` 通过；冻结结论同步到验证清单引用的位置。

### AV1-P02 虚构验收资料与人工标注（已完成，2026-08-06）

**目标与范围**

- 形成 12～18 份虚构资料，覆盖六个资料类型以及 PDF、DOCX、TXT、MD；增加 2～3 份异常样本。
- 为每份资料标注类型、可识别字段和标准证据；准备 8 个有据、2 个无据、2 个隔离固定问题。
- 样本与标注不含真实商业秘密、个人敏感信息或未获授权资料。

**完成条件**

- 生成器和标注格式受版本控制；生成的本地资料位于 `tests/pytest_docs/` 并由 Git
  忽略，目录缺失时测试自动调用生成器重建。
- 其仅作为质量评测 Ground Truth；不作为真实工程归档规则，也不直接决定模型 Prompt。

**完成结果（AV1-P02，2026-08-06）**

- 已生成 12 份正常虚构资料（六类资料各 2 份，覆盖 PDF、DOCX、TXT、MD）和 3 份
  异常资料（字段缺失/分类混淆、同项目原文件哈希重复、无可提取文本的扫描 PDF）。
- 已生成字段与证据 Ground Truth、12 个固定问题（8 有据、2 无据、2 项目隔离）及本地
  查看说明；`tests/services/test_archive_v1_evaluation_data.py` 验证资料、证据、重复哈希和问题集契约。
- 本任务未调用 DeepSeek，也未执行 Chroma 检索、阈值标定或问答质量评分；这些结果仍分别由
  AV1-P11、AV1-P12 与 AV1-P14 产生。

### AV1-P03 数据库、模型与公共授权基础（已完成，2026-08-06）

**目标与范围**

- 在 `0004_remove_leave_domain` 后创建前向 `0005_archive_v1_schema`，实现 `projects`、归档文档/快照/字段/证据、清单/关联、操作/审计等已确认结构和约束。
- 依数据库设计将 `documents.content_hash` 演进为原文件 `file_hash`，建立项目关系、容量计数、同项目哈希唯一性和与知识库的一对一范围约束；不把旧文档自动转换为档案。
- 新增 `ProjectContext` 所有权依赖、归档枚举、稳定错误码基础和最小 Schema/Model；保留现有 Agent、聊天和旧知识库行为。

**测试与完成条件**

### AV1-A01 账号密码认证、JWT 会话与身份切换（已完成隔离验证，FR-019～FR-021）

**目标与范围**

- 新增公开注册、登录、刷新和注销接口；使用全局唯一小写 `username` 登录，保留 `name` 作为显示名。
- 使用 Argon2 密码哈希与带 `sub`、`sid`、用途、签发/过期时间的 JWT；Access Token 30 分钟，
  Refresh Token 7 天。
- 增加 `auth_sessions` 表，只保存 Refresh Token 哈希、过期时间和撤销状态；刷新只签发新的
  Access Token，不轮换 Refresh Token。
- 将 `CurrentUserDep` 从 `X-User-ID` 完全切换为 Bearer Access Token，移除公开 `/users` 模拟身份入口。
- 旧用户保留业务归属数据但无凭据不能登录；提供不打印密码、不列举用户的本地初始化命令，按
  明确的用户 ID 设置用户名和密码。

**验证重点**

- 注册用户名规范化冲突、弱密码拒绝、密码哈希不回显，以及用户名不存在和密码错误的响应一致。
- 登录、刷新、注销、过期、伪造、用途错误和已撤销 Refresh Token 均返回稳定结果。
- 所有旧知识库、Agent、项目和聊天 API 均改用 Bearer Access Token；仅携带或伪造
  `X-User-ID` 必须不能通过身份校验。
- PostgreSQL 迁移前向兼容旧用户；迁移、模型约束、路由和服务测试不读取真实 `.env` 或数据库数据。

**实际验证与未验证项**

- 已通过隔离 SQLite 的注册、登录、刷新、注销、用途错误、旧 `X-User-ID` 拒绝、旧用户拒绝登录、
  会话撤销和既有受保护路由回归测试。
- revision `0010_account_auth` 已通过 SQLite 前向迁移和注释契约测试，并已在当前 PostgreSQL
  开发库实际前向迁移；已核对认证表、字段、索引及 Refresh Token 哈希唯一约束。

#### AV1-P04.2 清单项 API、版本控制与派生状态（已完成，FR-031）

**目标与范围**

- 提供 `GET/POST/PATCH/DELETE /projects/{project_id}/checklist-items`，只允许项目所有者访问和维护项目独立清单项。
- `POST` 创建清单项必须校验 `expected_project_version`；在同一事务中创建清单项、写入脱敏审计并使 `projects.version` 原子加一。清单项修改使用其 `expected_version` 防止覆盖新数据；旧版本均返回 `409 VERSION_CONFLICT`。
- 清单列表实时派生 `SATISFIED`、`MISSING`、`NOT_PROVIDED` 和 `confirmed_document_count`。只有同项目 `CONFIRMED` 档案与 `CONFIRMED` 关联同时存在才为 `SATISFIED`；必需项无满足关联为 `MISSING`，可选项无满足关联为 `NOT_PROVIDED`。不得仅按资料类型或项目阶段自动判定满足。
- 修改清单项的名称、资料类型或项目阶段时，使已有确认关联失效并重算状态；仅修改说明不影响关联。删除清单项时删除其关联并写入脱敏审计。
- 本任务只实现清单项维护和读取已有确认关联后的派生结果；不提供档案—清单项关联建议、创建或删除接口，该部分仍由 AV1-P10（FR-037）实现。

**验证重点**

- 模板复制后的项目清单可以独立增删改，跨项目或跨用户不能读取、修改或删除。
- 创建请求的旧项目版本、修改请求的旧清单项版本均返回稳定的 `409 VERSION_CONFLICT`，且不产生重复清单项或审计成功记录。
- 当前尚无已确认关联时，必需项返回 `MISSING`、可选项返回 `NOT_PROVIDED`；后续存在已确认档案和已确认关联时才返回 `SATISFIED`。
