# NFR-021 日志按日期分层实施计划

## 1. 目标与可验收行为

应用文件日志按日志记录的本地日期存储：

```text
<LOG_FILE 父目录>/<YYYY>/<MM>/<YYYY-MM-DD><LOG_FILE 扩展名>
```

默认 `LOG_FILE=./logs/app.log` 在 2026-09-14 生成：

```text
./logs/2026/09/2026-09-14.log
```

验收要求：

1. 年、月目录分别使用四位年和两位月。
2. 主日志文件名为 ISO 日期；保留 `LOG_FILE` 的扩展名，无扩展名时使用 `.log`。
3. 服务跨过午夜、月份或年份边界后，下一条日志自动切换到新日期路径，不依赖重启。
4. 继续使用现有 `LOG_MAX_BYTES` 和 `LOG_BACKUP_COUNT` 按大小轮转，备份位于当日目录。
5. 保留控制台日志、request ID、日志格式和重复配置防护。

## 2. 设计与边界

- 在 `app/core/logging.py` 提供可单测的日期路径构造函数。
- 在 `RotatingFileHandler` 基础上增加按 `LogRecord.created` 本地时间选择日期路径的处理器；路径变化时关闭旧文件并延迟打开新文件。
- `Settings.log_path` 仍只负责将 `LOG_FILE` 解析为绝对基准路径；不改变配置键。
- 不迁移、重命名或删除现有 `logs/app.log*`，也不读取实际日志内容。
- 不改变 HTTP API、数据库、Chroma、Agent 或业务审计行为。
