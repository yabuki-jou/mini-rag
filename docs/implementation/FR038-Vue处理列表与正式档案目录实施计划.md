# FR-038 Vue 处理列表与正式档案目录实施计划

## 1. 目标与边界

本切片把后端已经实现的 FR-038 文档处理列表、正式档案目录和档案详情接入相邻 Vue 工作台。处理列表用于查看全部处理状态；正式档案目录只展示后端返回的 `CONFIRMED` 档案，并支持已确认契约中的分页和筛选条件。

本切片不修改后端公开 API、数据库结构、正式档案判定规则、检索问答、物理删除或审计能力。前端不得把处理列表中的非正式文档拼装成正式档案，也不得自行推断归档状态。

## 2. 既有契约

- `GET /projects/{project_id}/documents`
  支持 `page`、`page_size` 和可选 `status`，返回文档处理列表及分页元数据。
- `GET /projects/{project_id}/archives`
  支持 `page`、`page_size`、`document_type`、`project_stage`、`document_date_from`、`document_date_to`、`document_date_is_null` 和 `authoring_organization`，只返回当前项目内可见的正式档案，按 `confirmed_at` 倒序排列。
- `GET /projects/{project_id}/archives/{document_id}`
  返回正式档案摘要和已确认的七项字段及证据；非正式、不可见或越权资源不作为档案详情返回。
- 合同资料的 `DOCUMENT_DATE` 在页面上解释为“合同签订日期”，其他资料解释为“文档日期”。

## 3. 实现步骤

1. 在前端类型层补充正式档案摘要、目录分页、详情和筛选条件 DTO。
2. 在 API 层完成三个读取方法：
   - 处理列表把状态和分页参数准确编码到查询串；
   - 正式档案目录只提交用户实际选择的筛选条件；
   - 档案详情使用独立详情接口读取，不复用草稿数据拼装。
3. 在 Pinia Store 保存处理列表分页元数据、状态筛选、正式档案目录分页元数据、筛选条件和当前档案详情：
   - 切换项目时清空旧项目列表、筛选和详情；
   - 请求返回时校验项目 ID、页码和筛选快照，丢弃过期响应；
   - 状态或目录筛选变化后回到第一页；
   - 详情关闭或切换档案时不显示旧档案字段。
4. 扩展文档处理面板，增加状态筛选、上一页/下一页和总数信息；现有上传、草稿、确认与关联入口保持可用。
5. 新增正式档案目录面板并接入 `archives` 路由：
   - 展示文件名、标题、资料类型、项目阶段、责任单位、文档日期和确认时间；
   - 支持资料类型、项目阶段、日期范围、日期为空和责任单位筛选；
   - 支持分页和查看详情；
   - 详情逐项展示确认值、证据定位与证据摘录；
   - 根据资料类型显示正确的日期语义。

## 4. TDD 与验收

### RED

先增加并实际运行失败测试，至少覆盖：

- API 的精确 URL、查询参数编码和详情路径；
- Store 的分页元数据、筛选回到第一页、项目与查询过期响应隔离、详情清理；
- 处理列表的状态筛选和分页事件；
- 正式档案目录的筛选、分页、详情字段与证据展示，以及合同日期语义；
- 工作台 `archives` 路由从占位内容切换为真实目录，并正确触发读取。

### GREEN

只实现使上述行为通过的最小前端代码，不修改后端业务规则或扩大到 FR-039～FR-041。

### 最终验证

1. 运行新增与相关前端测试。
2. 运行前端完整测试、`typecheck` 和 `build`。
3. 运行后端 FR-038 相关测试、完整测试和 `compileall`。
4. 使用真实 `5173/api -> 8000` 链路验收：处理列表包含非正式与正式状态；状态筛选和分页参数生效；正式目录只出现已确认档案；各筛选、详情、证据和刷新持久化符合服务端数据；取消确认后档案从正式目录消失。
5. 精确清理临时用户、项目、文档、原文件和向量数据，再更新交接文档。

## 5. 停止条件

若实现需要改变公开 API、核心数据库结构、正式档案可见性规则、日期字段语义或项目隔离边界，Luna 停止扩大修改并交回主 Agent重新评审。
