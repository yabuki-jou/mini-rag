# Agent 演示步骤

前置条件：当前代码版本需要 PostgreSQL、Chroma、Embedding 与 API 健康，知识库中已有一份解析
完成的企业制度或项目管理文档。Chroma 独立可行性与本地代码迁移已完成；旧制度 Agent 的向量
重建和真实服务回归仍需按其独立资料确认。本演示仅是本地开发演示，不能用档案 V1 的验收结果
替代旧制度 Agent 的质量证据。

1. 创建用户和知识库，上传并解析文档。
2. 创建绑定该知识库的 Agent 会话。
3. 询问文档中有明确依据的问题，展示回答、文档名、页码、摘录和分数。
4. 询问知识库中没有依据的问题，展示明确拒答而不是编造。
5. 连续发送两轮相关问题，再读取 `/messages` 展示 Checkpoint 恢复的历史。
6. 读取 `/tool-calls`，展示工具名、耗时、完成/失败状态和脱敏摘要。
7. 使用另一个用户读取该会话，展示 403 所有权保护。

演示时必须明确：业务库是 PostgreSQL，SQLite 只用于 LangGraph Checkpoint；
智慧档案与企业文档智能已完成 Parser 规则冻结、虚构验收资料、数据库/模型/公共授权基础
P04 前置模型分层、项目 CRUD/模板复制 API、清单项 CRUD/派生状态 API、P05 项目内上传、P06 正式解析/快照/重试、P07 手工草稿/字段检查、P08 AI 建议/安全 regenerate、P09 确认/INDEX/取消确认、P10 清单关联/目录/审计、P11 正式检索、P12 证据问答和 P13 物理删除；P14-D6-B 固定质量门、P13 真实恢复、企业扩展集和 FR-034～FR-041 Vue 分阶段真实代理链路已通过。当前不推进标书投标、标书解析生成或投标合规审查，请假领域已经删除。

档案 V1 的最终验收范围与限制见 `docs/review/验收报告.md`。不得把本 Agent 的制度演示
当作档案 V1 质量证据，也不得反向用档案问答验收替代旧制度 Agent 的独立回归。
