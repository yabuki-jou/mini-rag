# Agent 演示步骤

前置条件：当前代码版本需要 PostgreSQL、Chroma、Embedding 与 API 健康，知识库中已有一份解析
完成的企业制度或项目管理文档。Chroma 独立可行性与本地代码迁移已完成；旧制度向量重建和真实
服务回归仍待完成；本轮已完成一次唯一 UUID 范围的 Final Collection/BGE 写入、查询和删除 canary。本演示仅是本地开发演示，云端部署是否进行及其验收方案均暂定至 V1 完成后。

1. 创建用户和知识库，上传并解析文档。
2. 创建绑定该知识库的 Agent 会话。
3. 询问文档中有明确依据的问题，展示回答、文档名、页码、摘录和分数。
4. 询问知识库中没有依据的问题，展示明确拒答而不是编造。
5. 连续发送两轮相关问题，再读取 `/messages` 展示 Checkpoint 恢复的历史。
6. 读取 `/tool-calls`，展示工具名、耗时、完成/失败状态和脱敏摘要。
7. 使用另一个用户读取该会话，展示 403 所有权保护。

演示时必须明确：业务库是 PostgreSQL，SQLite 只用于 LangGraph Checkpoint；
智慧档案与企业文档智能已完成 Parser 规则冻结、虚构验收资料、数据库/模型/公共授权基础
P04 前置模型分层、项目 CRUD/模板复制 API、清单项 CRUD/派生状态 API、P05 项目内上传、P06 正式解析/快照/重试、P07 手工草稿/字段检查、P08 AI 建议/安全 regenerate、P09 确认/INDEX/取消确认、P10 清单关联/目录/审计、P11 正式检索、P12 证据问答和 P13 物理删除切片；真实确认—INDEX、Chroma/BGE canary、取消确认清理和单文档 P95 基线已通过。P14 固定集复验未能冻结纯稠密检索阈值；DeepSeek 质量、P13 真实跨存储恢复和完整端到端验收仍待完成。当前不推进标书投标、标书解析生成或投标合规审查，请假领域已经删除。

档案 V1 当前已提供 P10～P13 的清单关联、处理列表/正式目录、正式检索、证据问答和物理删除切片；
P11 单文档真实 canary 的 P95 约 125.97 ms。固定问题集质量、DeepSeek 质量、P13 真实跨存储恢复
和完整 Swagger 端到端验收仍待 P14，不得把本 Agent 的制度演示当作档案 V1 质量证据。
