## 1. 要解决的问题

P153548 的冻结问题询问“世界银行贷款”，原始措辞与目标资料中的 `IBRD` 不对齐。真实 Chroma 诊断显示：目标证据在原问题 dense Top-30 中缺失；保留原问题候选并补充 `IBRD IDA` 候选后，公开证据覆盖在补充表达重排中进入 Top-8（第 3）。把同一并集按两种表达送入真实回答判定的既有单题对照中，补充表达重排条件三次均引用冻结目标页；这些结果尚未接入正式代码。

本计划要把窄方案接入 FR-039 与 FR-042 共用的回答候选检索路径，并验证目标证据从召回到最终引用都保留下来。目标是“检索能把支持原文交给回答层”，不是让模型将“世界银行”替换成 `IBRD` 来回答，也不是声称两者在所有语境下等价。

2026-09-25 只读补充对照在四份 P153548 PDF 的 190 个原文页片段上，以当前本地 BGE/CrossEncoder 比较固定裸词 `IBRD IDA` 与整题替换：目标页 dense 名次分别为 13/8，原路与补充路并集分别为 53/44，按各自表达重排后均为第 3。Belarus Snapshot 20 页上，固定裸词重排使第 7 页背景/金额页为第 18、第 16 页 IBRD 贷款表为第 7；整题替换分别为第 2/第 1。该对照未写 PostgreSQL/Chroma、未调用 DeepSeek；原文页片段不含正式索引 `evidence_values`，因此仅支持继续验证固定裸词方案，不构成正式检索或答案引用通过。

## 2. 代码落点与边界

- FR-039 的问答和 FR-042 的 `search_confirmed_archive_evidence` 均调用 `retrieve_archive_answer_candidates`；修改共享回答候选服务即可覆盖两条链路。
- FR-042 工具的 `query` 是模型生成的检索词，可能与用户原话不同。贷款意图门控必须检查当前轮原始 `HumanMessage`；不得只依赖模型改写。FR-039 的门控文本就是原始用户问题。
- 只修改回答候选检索，不改变 `retrieve_archive_chunks` 通用检索接口、诊断接口、公开 API Schema、数据库/Chroma 结构、Prompt、Agent 工具预算或会话语义。
- 原始用户问题继续作为 FR-039/FR-042 最终回答判定输入；`IBRD IDA` 只用于内部补充 dense 查询及该分支的 CrossEncoder 排序。
- 不改固定 P153548 数据、答案/引用质量门或 `.env`。不引入 RRF、分数融合、统一 Chunk 重切分、向量模型更换、通用实体归一化或更改全体问题排序。

## 3. 方案

### 3.1 保守门控

仅当同一轮用户意图同时出现以下两类白名单信号时触发补充召回：

- World Bank 指称：`世界银行`、`世行`、`World Bank`（英文大小写不敏感）。
- 明确贷款/融资意图：`贷款`、`融资`、`loan`、`lending`、`financing`（英文大小写不敏感）。

不把 `资金`、`funding`、机构介绍或项目背景单独视作贷款意图；`IFC`、`MIGA` 不作为 World Bank/IBRD/IDA 别名。确定性白名单和边界写入测试，禁止模型判断门控。

FR-042 只读取 Graph State 中当前轮最新用户 `HumanMessage` 作为门控意图；不把旧轮历史或模型生成的工具查询拼接进门控。明确仅回答“贷款金额呢”这类省略机构名的追问不在首版触发保证内；实现时不得悄悄扩大为历史语义推断。

### 3.2 双路候选与最终排序

未命中门控：保持现在的单路行为完全不变（一次原查询 Chroma dense Top-30、一次原查询 CrossEncoder、原有 Top-8）。

命中门控：

1. 用既有 FR-039/FR-042 检索查询执行原始 Top-30；原始结果全部保留。
2. 再以固定裸词查询 `IBRD IDA` 执行一次 Top-30；它不包含原问题上下文，也不是将术语替换进完整问题。不得把补充词追加到原问题末尾。
3. 两路均复用同一组服务端 `user_id + project_id + kb_id + CONFIRMED document_ids` Chroma 过滤和 PostgreSQL 正式/删除可见性校验；响应候选仍逐项复核正式文档范围。
4. 按 `chunk_id` 稳定去重，合并池不截断，理论上限 60。重复项优先保留原始路对象；只在补充路命中的候选保留其自身元数据。禁止跨不同查询的 dense 分数相加或平均。
5. 对整个合并池只运行一次 CrossEncoder：将固定裸词 `IBRD IDA` 交给现有 `_build_archive_reranker_query_expression`，以构造后的生产查询表达重排，返回前 8 项；不得绕过现有 C4-A/C4-B 表达构造。既有正式 Chroma 的第 22→第 3 和 3/3 引用来自整题替换，不得当作裸词方案的正式质量证据；裸词仅有上文原文页进程内对照支持，仍须通过 §5.2/§5.3 的正式索引与引用门。
6. 返回字段、候选/引用映射和最终回答问题保持现有契约。内部 supplemental 查询不新增 Tool Call，不把检索表达展示给用户，不将资源 UUID、Chunk ID 或分数交给 FR-042 模型。

本策略在触发问题上会额外执行一次 Embedding/Chroma 查询，并可能将 CrossEncoder 输入从 30 扩至最多 60 条。现有延迟数据不足以设定稳定预算；必须分别记录两路 dense、并集大小、单次并集 Reranker 耗时与端到端耗时，不伪造线上 P95 结论。
