# 关注项

## 1. 优先风险

| 优先级 | 问题 | 证据 | 影响 | 建议 |
|---|---|---|---|---|
| 高 | `X-User-ID` 是模拟身份，不是认证 | `app/dependencies/auth.py`、`AGENTS.md` | 知道 UUID 的客户端可伪造用户 | 保持学习边界，后续 JWT 从受验证 Token 注入身份 |
| 高 | 进度事实分散在 README、学习计划、设计、实施与验收文档 | `README.md`、`LEARNING_PLAN.md`、`docs/智慧档案V1实施计划.md` | 后续开发可能把已完成/未完成能力判断错 | 本轮已同步至 P04.1 项目 API；后续每个任务验证后必须同步这些文档 |
| 中 | Router 存在直接 Session 查询/提交 | `app/routers/users.py`、`knowledge_bases.py`、`documents.py` | 与 Router→Service 约定不一致，后续领域规则易重复 | 旧接口不必立即重构；新 `/projects` 接口必须从第一天经 Service |
| 中 | SQLite 与 PostgreSQL 的测试语义不同 | `tests/`、`app/db.py` | SQLite 通过不代表 PostgreSQL 方言行为 | 需要 PostgreSQL 的场景继续使用显式可选测试 |
| 中 | 同步解析、BGE、Chroma 和 DeepSeek 运行在请求线程 | `app/services/archive/documents.py`、`app/services/rag/chat.py` | 大文件或并发会阻塞请求 | V1 保持同步并记录耗时；验证后再决定队列/异步任务 |

## 2. 结构与类划分债务

| 项目 | 现状 | 风险 | 建议 |
|---|---|---|---|
| `agent/sessions.py` | 618 行，混合 Graph 执行、Checkpoint 映射、审计和响应组装 | Agent 修改时高耦合 | 下次 Agent 功能变更时拆为执行、消息映射、审计三个模块 |
| 归档模型 | 已拆为 `project.py`、`archive.py`、`checklist.py`、`archive_audit.py` | 新模型若绕过 `app.models` 公共导出，可能造成导入入口不一致 | 新业务代码优先从 `app.models` 导入；仅在模块内部需要专用常量/枚举时直接导入对应模块 |
| `rag/vector_store.py` | 172 行，仅保留旧 Collection Schema、插入与删除；Chroma 客户端已集中在 `infrastructure/chroma.py` | 复用正式归档 Collection 时职责变多 | 将新归档索引实现为独立适配器，不污染旧 Collection 服务 |
| `archive/documents.py` / `rag/documents.py` | 两条文档生命周期分别负责档案解析与旧知识库向量化 | 交叉调用会混淆两个状态机 | 通过 `archive.reads` 共享只读投影，生命周期服务不互相调用 |

## 3. 安全

| 风险 | 类别 | 现有缓解 | 缺口 |
|---|---|---|---|
| 模拟身份请求头 | A07 身份认证失败 | 真实用户存在性和资源所有权检查 | 不可抵御主动伪造 |
| 外部模型数据 | N/A（业务数据边界） | 需求限制仅虚构/脱敏资料 | 尚无上传内容自动敏感信息检测 |
| 跨存储删除 | N/A | 旧文档状态补偿与精确 Chroma 过滤 | 进程崩溃后仍需人工/后续恢复策略 |

## 4. 性能与扩展

| 问题 | 证据 | 规模化风险 | 建议 |
|---|---|---|---|
| 同步重任务 | `archive/documents.py`、`infrastructure/ai_models.py` | Web worker 被解析或模型推理占满 | 在 AV1 验收后基于实测决定后台任务 |
| SQLite Checkpoint | `app/agents/admin/runtime.py` | 多实例/并发写入不适合 | 只有部署需求出现时再迁移 Checkpoint 存储 |
| 无统一超时/熔断 | `infrastructure/ai_models.py`、`rag/vector_store.py` | 外部故障占用请求资源 | 为外部客户端增加受控 timeout，保持只重试连接/超时 |

## 5. 高变更区域

最近 90 天 Git 记录显示 `app/main.py`、`app/core/config.py`、`app/db.py`、`app/services/infrastructure/ai_models.py`、`app/services/rag/vector_store.py` 和设计文档有较高修改次数；历史路径中已删除的 `app/models/leave.py`、`app/schemas.py` 不应作为当前实现依据。

## 6. 已确认的 P04 分层基线

1. 智慧档案模型已拆为 `project.py`、`archive.py`、`checklist.py`、`archive_audit.py`；表名、字段、约束和 `app.models` 公共导入入口不变，因此不需要数据库迁移。
2. 不回头重构旧用户、知识库和文档列表 Router；从新的 `/projects` 接口开始严格执行 `Router → Service`，避免 P04 被旧模块整理阻塞。
