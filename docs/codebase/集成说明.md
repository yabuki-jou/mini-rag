# 外部集成

## 1. 集成清单

| 系统 | 类型 | 用途 | 认证/配置 | 关键性 | 证据 |
|---|---|---|---|---|---|
| PostgreSQL | 业务数据库 | 用户、文档、Agent、归档业务事实 | `DATABASE_URL` | 高 | `app/db.py`、`migrations/` |
| SQLite | 本地状态库 | 仅 LangGraph Checkpoint | `AGENT_CHECKPOINT_FILE` | 中 | `app/agents/admin/runtime.py` |
| 本地文件系统 | 文件存储 | 原始上传文件、日志、解析快照规划 | `FILE_STORAGE_DIR`、`LOG_FILE` | 高 | `app/services/file_service.py` |
| Milvus | 向量数据库 | 旧 RAG Chunk 的写入、检索、精确删除 | URI、Token、Collection | 高 | `app/services/vector_service.py` |
| 本地 BGE | 模型 | 文档和查询 Embedding | 模型路径、设备、维度 | 高 | `app/services/model_service.py` |
| DeepSeek | 外部 LLM API | 旧 RAG 回答与制度 Agent | API Key、URL、模型 | 中 | `app/services/model_service.py` |

## 2. 数据边界

| 存储 | 事实来源 | 访问层 | 主要风险 |
|---|---|---|---|
| PostgreSQL | 业务身份、状态、审计和归档领域 | SQLModel + Alembic | Milvus/文件系统之间无分布式事务 |
| SQLite | Agent 图执行状态和消息 Checkpoint | `AdminAgentRuntime` | 单机文件锁与多实例扩展限制 |
| 文件系统 | 原文件 | `file_service.py` | 删除与数据库状态需要补偿 |
| Milvus | 可重建的 Chunk/向量索引 | `vector_service.py`、`retrieval_service.py` | 旧链路的“解析即入库”不能用于正式档案 |

## 3. 密钥与配置

- `.env` 由 `Settings` 读取，`.env.example` 是可提交模板；真实 `.env` 被忽略。
- DeepSeek API Key 和 Milvus Token 使用 `SecretStr`，但客户端构造时会取出真实值用于连接。
- 未发现密钥轮换、Secret Manager 或生产多环境配置机制。[TODO]

## 4. 可靠性行为

- Agent ToolNode 只对 `TimeoutError`、`ConnectionError` 使用最多 3 次重试。
- 文件删除和旧文档删除具有幂等/补偿逻辑；Milvus 写入、检索与 DeepSeek 错误转换为 `AppError`。
- 未发现 DeepSeek、Milvus 或 BGE 的统一 timeout、熔断器、限流或后台队列。[TODO]

## 5. 可观测性

- HTTP 请求使用 request ID；旧文档处理、检索、Agent 工具记录资源 ID、数量和耗时。
- Agent 工具日志保存脱敏摘要；不保存制度全文或内部异常正文。
- 未发现 Metrics、分布式 Trace、集中日志或告警集成。[TODO]
