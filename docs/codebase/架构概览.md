# 当前代码架构

当前正式能力只有智慧档案 V1、FR-039 档案问答和 FR-042 项目档案助手。通用知识库、普通 Chat 和制度 Agent 已从应用入口下线；历史表、迁移、Checkpoint、Collection 和文件仅为兼容/追溯保留。

## 1. 架构风格

- 主体是同步 FastAPI 模块化单体，目录按横向层划分。
- 请求一般经 `Router → Dependency → Service → PostgreSQL / 文件系统 / Chroma / DeepSeek`。
- FR-042 项目档案助手使用 LangGraph 与受控档案只读工具；Checkpoint 保存到独立 SQLite。
- 智慧档案当前已实现 P01～P14：归档模型、迁移、`ProjectContext`、独立 Parser、项目与清单 CRUD、项目内上传、解析快照、草稿、建议、确认/索引、目录、审计、正式检索、证据问答和删除恢复。

## 2. 当前正式数据流

```text
项目/文档 Router → ProjectContext → `archive/*` 服务
→ 文件系统与解析快照 → 人工确认 → Chroma 正式索引 → PostgreSQL 档案事实

FR-039/FR-042 → 项目范围与正式档案校验 → Chroma 检索或档案 LangGraph
→ DeepSeek → 引用/拒答、Checkpoint 与脱敏审计/工具记录
```

`app/main.py::lifespan()` 在启动时先执行 `upgrade_database()`；正式 Schema 由 Alembic 而非 `create_all()` 建立。

## 3. 各层职责

| 模块 | 当前职责 | 不应承担 | 证据 |
|---|---|---|---|
| Router | HTTP 契约、依赖注入、调用服务 | Chroma、DeepSeek、跨存储补偿 | `app/routers/projects.py`、`app/routers/archive_agent.py` |
| Dependency | 当前用户和资源所有权；项目范围绑定 | 归档确认、清单计算 | `app/dependencies/resources.py`、`project_context.py` |
| Service | 状态迁移、事务、外部资源调用 | FastAPI 响应对象 | `app/services/archive/`、`app/services/project/` |
| Agent | FR-042 Prompt、Graph、工具调用观测、Checkpoint | SQLModel Session 生命周期 | `app/agents/archive/` |
| Model / Schema | 分别表达持久化事实与 HTTP 契约 | 复用为可写入的同一对象 | `app/models/`、`app/schemas/` |

## 4. 重复使用的模式

| 模式 | 位置 | 目的 |
|---|---|---|
| FastAPI typed dependency | `CurrentUserDep`、`Owned*Dep`、`ProjectContextDep` | 将身份与资源范围在进入路由前固定 |
| 应用错误 | `AppError` | 统一稳定错误码并隐藏内部异常 |
| 缓存客户端 | `lru_cache` 的模型/Chroma 客户端 | 避免进程内重复加载模型和连接配置 |
| 不可变数据载体 | `TextChunk`、`EmbeddedChunk`、`RetrievedChunk`、`ParsedArchiveDocument` | 限制流水线中间值被意外修改 |
| 显式补偿状态 | `DocumentStatus`、`ArchiveOperation` | 处理文件/向量/数据库非原子操作 |

## 5. 类与模块划分判断

- `User`、`KnowledgeBase`、`Document`、Agent 的模型已按领域拆分；Pydantic Schema 独立，划分合理。历史 Chat 表仍由迁移保留，但不再作为当前 SQLModel 业务入口。
- `ProjectContext` 是小型不可变值对象，放在 dependencies 合理：它是授权范围，不是持久化实体。
- 归档模型已按职责拆分：`project.py` 管理项目隔离与容量计数，`archive.py` 管理档案/快照/字段/证据，`checklist.py` 管理项目清单与人工关联，`archive_audit.py` 管理内部操作和脱敏审计。`app.models` 保持原有公共导出，调用方无需跟随文件移动改写导入。
- Agent 应用服务已按职责拆分：`sessions.py` 创建会话，`messages.py` 转换 Checkpoint 消息与引用，`audit.py` 持久化脱敏工具审计，`execution.py` 执行 Graph 并保持提交和错误映射边界。
- `archive/documents.py` 只负责项目档案上传、解析快照和解析重试；正式向量化、检索与删除均按项目档案范围执行。

## 6. 已知架构风险

- 历史迁移和兼容模型仍可能保留旧领域命名；它们不构成当前 API 或业务能力。
- PostgreSQL 是当前业务库；SQLite 仅用于 LangGraph Checkpoint 和隔离测试。
- 同步解析、BGE 与 DeepSeek 调用会占用请求线程；这是已知 V1 范围限制。
