# 代码约定

## 1. 命名规则

| 项目 | 当前规则 | 示例 | 证据 |
|---|---|---|---|
| 文件 | `snake_case.py`，按资源或服务命名 | `project_context.py`、`rag/vector_store.py` | `app/` |
| 函数 | `snake_case`；模块私有函数以 `_` 开头 | `_safe_result()`、`retrieve_chunks()` | `app/services/agent/sessions.py` |
| 类型 | `PascalCase` | `ArchiveDocument`、`AgentResponse` | `app/models/`、`app/schemas/` |
| 常量/环境变量 | `UPPER_SNAKE_CASE` | `MAX_PARSED_TEXT_CHARACTERS`、`DATABASE_URL` | `app/services/archive/parser.py`、`.env.example` |

## 2. 格式化与静态检查

- 未发现配置化的 Formatter、Linter、Mypy 或覆盖率门槛。[TODO]
- 实际可运行检查为 pytest、`compileall`、Alembic 迁移测试和 `git diff --check`。
- 公共函数、模型类和关键状态转换普遍带类型标注与中文职责文档字符串。

## 3. 导入与模块规则

- 导入顺序通常为标准库、第三方库、`app.*`；使用绝对导入。
- `app.models`、`app.schemas`、`app.dependencies` 通过 `__init__.py` 提供稳定导入入口。
- SQLModel 是持久化模型，Pydantic Schema 是 HTTP 契约；不应把 SQLModel 当作可写请求体。

## 4. 错误与日志

- 预期业务错误使用 `AppError(status_code, code, message)`。
- 写入失败先 `rollback()`；未知异常只写服务器日志，由全局异常处理器返回 `INTERNAL_ERROR`。
- 日志通过 `RequestContextMiddleware` 附带 request ID；工具审计仅保存参数/结果脱敏摘要。
- 约定与事实漂移：一些旧文档字符串仍将 PostgreSQL 业务 Session 表述为 SQLite，应在接触文件时修正，不能据此修改架构判断。

## 5. 测试约定

- 测试文件位于 `tests/test_*.py`，使用 pytest 的普通 `assert`、`monkeypatch`、`Mock` 和 FastAPI dependency override。
- 绝大多数测试使用隔离 SQLite 或 Mock；`POSTGRES_TEST_URL` 是显式可选的空库迁移测试。
- 当前没有配置覆盖率阈值。[TODO]
